# Excelゲート MVP6th

HTMLを指定して「Excelゲートに組み込んで」と依頼すると、この作業環境のAIがコピーの適合、ブラウザ試験、配布準備を行います。組み込み者がJavaScript・VBA・設定JSONを編集したり、コマンドを入力したりする必要はありません。

既存画面・業務JSON・閲覧時の検索と表示切替を維持します。HTML作成者は通常のHTMLを渡し、導入担当者1人が業務上の動作確認と共有場所への導入を行います。

## 現在の状態

**共通ブック `MVP6th.xlsm` の作成と、埋め込みコード・初回設定ボタンの照合が済みました。修正前の版ではWindows版JUST Calcからの保存・再読込の本人報告があります。今回の修正版と二台での実機検収は未完了で、まだ配布可能・利用開始可能ではありません。**

AI向け組み込み手順、原本保管・更新管理、自動試験、配布フォルダ／ZIP作成、共通本体・アプリ・導入先の検証記録を実装しました。確認結果は [検証記録](docs/verification.md) にまとめています。

## マクロ入りの共通ブックは、誰が・いつ作るか

**共通ブックの作成は、Excelゲート本体を提供する側の作業です。** 本体開発を担当するAI・開発者が、アプリの通常配布に進む前に用意します。アプリ追加時には、AIが完成済みの共通ブックのコピーと、改修したHTMLを配布フォルダにまとめます。本体のVBAを変更しない限り、アプリごとのマクロ編集やブックの組み立ては不要です。

完成までの順序は次のとおりです。

1. **共通ブックを作る。** Windows版Excelの作成スクリプト、または [Mac版Excelの手作業手順](docs/build-workbook-mac.md) で、テンプレートへ共通VBAと操作ボタンを組み込み、`MVP6th.xlsm` として保存します。埋め込んだコードが元のソースと一致することも確認します。Macの手作業には、既存テンプレートと貼り付け用コードを使えます。
2. **HTMLと組み合わせて検証する。** AIが適合済みHTMLと共通ブックを組み合わせ、ブラウザ試験に加えてWindows／JUST Calc／Edgeで本体・アプリを検証します。合格したものを「配布可能」とします。
3. **共有場所で初回設定と導入確認をする。** 配置したコピーの「初回設定」は、共有場所やアプリの情報を登録する操作です。この時点ではマクロは組み込み済みです。保存・再読込・二台での編集交代などを確認して「利用開始可能」とします。

Mac版Excelでのコンパイル成功、`GateShowSetupPanel` の実行、初回設定ボタンの表示、保存、閉じて開き直しても正常だったことは、作成者から報告を受けています。保存済みファイルのコードとボタンはAIが照合しました。

必要な環境、具体的な作成手順、完成の判定は [共通ブックの作成](docs/build-workbook.md) に記載しています。組み込み者がこの作業をアプリごとに行う想定ではありません。

## 技術的な仕組み

### 何がどの役割を持つか

日常の動作は、HTML側のJavaScriptとブック側のVBA（マクロ）が、コードに書かれた手順で行います。Excelゲートの標準処理にAIの呼び出しはありません。AIは組み込み・改修・試験を担当し、変更したコードと確認結果をファイルに残します。

| 部品 | 役割 |
| --- | --- |
| 業務HTML | これまでの画面を表示し、入力・検索・表示切替などを行います。編集中のデータを持ちます。 |
| 共通JavaScript | 業務HTMLをゲートにつなぎ、編集できる状態の判定や、ブックへ渡すファイルの作成を行います。 |
| 共通ブックとVBA | 正式な保存データをブック内に持ち、HTMLの起動、受け渡しファイルの検査、保存と復旧を担当します。 |

### データが保存されるまで

次の流れをソースに実装しています。完成ブックを使った対象環境での確認は、上記「現在の状態」のとおり未実施です。

1. **ブックから開く。** VBAが保存済みデータと今回の編集を識別する情報を用意し、一時フォルダに作ったHTMLをEdgeで開きます。画面は `file://` で動きます。
2. **HTMLで入力する。** 変更内容は画面側に保持されます。元のHTMLにブラウザ内の自動保存・復元がある場合は、ブックから受け取ったデータと混ざらないよう、組み込み時にAIが調整します。
3. **受け渡しファイルを出す。** 「入力を終える」などの操作で、JSON（データを文字で表した形式）をダウンロードします。元の業務データの形を保ち、その外側にブック・アプリ・今回の編集の識別情報や出力順序を付けます。
4. **ブックで正式保存する。** ブックの保存操作でVBAがファイルを読み、対象や出力順序を照合してから保存します。別のブック用・古い編集用などのファイルは拒否し、受け入れたJSONは復旧用にも保管します。

**HTMLでファイルを出しただけでは正式保存は完了しません。ブック側の保存完了を確認します。** このファイル経由の受け渡しにより、ゲート用のサーバーや利用者PCへの追加開発ツールを不要にしています。元のHTMLが外部サービスを使う場合、その通信や接続条件は別途確認します。

閲覧画面には、開いた時点の保存済みデータを表示します。自動更新は行わないため、最新の内容を見るときはブックから開き直します。

### AIがHTMLに加える接続処理

AIは原本を保管し、コピーを調べて、次の4つを `ExcelGate.connect(...)` に接続します。業務ごとのデータ構造や入力方法を読む必要があるため、共通スクリプトだけで任意のHTMLを自動変換する仕組みではありません。

| 接続する処理 | 意味 |
| --- | --- |
| `load` | ブックから受け取った正式データを業務画面へ読み込みます。初回起動と、保存済みの空データを区別します。 |
| `exportData` | 現在の業務データを取り出します。入力途中の内容を確定できない場合は、理由を表示して出力を止めます。 |
| `setReadOnly` | 閲覧中のデータ変更を禁止し、検索や表示切替は使えるようにします。 |
| `ready` | 画面の初期化が終わるまで待ち、読み込みの順序をそろえます。 |

さらに、業務操作でデータを変更する箇所へ `ExcelGate.assertEditable()` を入れます。これは「今は編集してよい状態か」を確認する処理で、ブックと連携している間は、閲覧中・起動途中・エラー時・終了用の出力後の変更を止めます。遅れて完了するデータ取込にも、実際の書き換え直前に接続します。ブックからの正式データの初期読み込みは、この制限の対象にしません。接続漏れがないかは、コードの確認とアプリごとの試験で調べます。

二台で同時に編集させない制御は、共有ブックの読み取り専用状態と、VBAが記録する編集中の識別情報を使います。共有フォルダとJUST Calcでこの制御が成立することは、二台での実機試験が必要です。

### 何を根拠に確認できるか

- **変更内容を追えるようにします。** 原本は `integrations/<アプリ名>/revisions/` 内、修正後HTMLは `apps/<アプリ名>/` 内に残り、比較できます。共通処理も [JavaScript](shared/excel-gate.js) と [VBA](vba/utf8/GateMain.bas) を読めます。
- **実際に動かした結果を残します。** データの読み込み・出力の往復、閲覧制御、未確定入力、遅れて動く処理などをブラウザで試験し、結果とログを保存します。対象ファイルから計算した照合値（ハッシュ）で、試験後のプログラム変更を検出し、再検証を要求します。この照合は「試験したものと同じか」の確認です。
- **業務上の正しさと実機動作を確認します。** AIが用意する試験だけでは、すべての操作や業務上の期待を保証できません。導入担当者の画面確認と、Windows／JUST Calc／Edgeでの保存・復旧・二台での編集交代の確認を組み合わせます。ブラウザ試験の合格だけで「利用開始可能」とはしません。

どこまで確認済みかは [検証記録](docs/verification.md)、試験対象と判定のルールは [検証の分類と記録](docs/acceptance-test.md) で確認できます。
