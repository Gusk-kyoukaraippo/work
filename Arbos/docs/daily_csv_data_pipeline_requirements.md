# 利用率分析データベース要件定義

## 目的

老健アルボースの利用率低下について、現時点で取れる入所者データをもとに、流入・滞在・流出・再入所の構造を見える化する。

目的は、完成版の業務システムやCRMを作ることではない。まずは、利用率低下の真因を決め打ちせず、最低限のデータベースを作り、以下の示唆を出せる状態にする。

- 月別の入所数
- 月別の退所数
- フロア別の在所者数
- フロア別の概算利用率
- 流入元別の件数
- 退所先別の件数
- 退所理由別の件数
- 長期入所者と短期退所者の分布
- 年間の延べ入所回数
- 実人数と延べ人数の違い
- 再入所者の数
- 再入所までの日数
- 退所後に戻ってきている人
- 病院退所後に再入所している人
- 自宅退所後に再利用できている人
- 特定の流入元から再入所につながっているか
- フロア別の滞在期間
- 長期入所化している人と短期反復利用の人

最終的な見せ方としては、以下を想定する。

- 年間入退所タイムライン
- 月別の入所・退所グラフ
- フロア別利用率ヒートマップ
- 流入元・退所先の構成グラフ
- 再入所者リスト

そのために、利用者を1人1行で管理するのではなく、**1回の入所を1行として管理する入所エピソード型のデータベース**を作る。

## データベース設計の基本方針

同じ利用者が入所・退所を繰り返す前提で設計する。

そのため、以下を必ず分ける。

```text
利用者ID: 人を識別するID
エピソードID: 1回の入所を識別するID
```

同じ利用者が再入所した場合は、同じ利用者IDのまま、新しいエピソード行を追加する。

過去の入所日・退所日は上書きしない。

## 最小データベース構成

初期MVPでは、以下の3テーブルを持てばよい。

1. 利用者マスタ
2. 入所エピソードテーブル
3. フロア定員テーブル

実装上は、最初から厳密なリレーショナルDBでなくてもよい。CSVやスプレッドシートで始める場合でも、この3テーブルの考え方に沿って列を作る。

## 1. 利用者マスタ

1人につき1行。

初期段階では、個人情報を避けるため、氏名は持たない。

| 項目 | 必須 | 型・例 | 内容 |
|---|---:|---|---|
| 利用者ID | 必須 | `00140931` | 匿名ID。毎日CSVの `患者ID` を使う |
| 備考 | 任意 | テキスト | 必要時のみ。初期は空欄でよい |

### 利用者マスタの役割

- 実人数を数える
- 同じ人の再入所を追う
- 延べ入所回数と実人数を分ける

### 初期では入れない項目

- 氏名
- カナ氏名
- 担当者
- 要介護度
- 医療依存度

これらは初回分析には入れない。理由は、入力負荷と個人情報リスクを増やす一方で、流入・滞在・流出の入口分析には必須ではないため。

## 2. 入所エピソードテーブル

1回の入所につき1行。

このテーブルが分析の中心になる。

| 区分 | 項目 | 必須 | 型・例 | 内容 |
|---|---|---:|---|---|
| 識別 | エピソードID | 必須 | `E_00140931_20250122` | 1回の入所を識別するID |
| 識別 | 利用者ID | 必須 | `00140931` | 利用者マスタに紐づくID |
| 期間 | 入所日 | 必須 | `2025-01-22` | 入所開始日。毎日CSVの `入院日` |
| 期間 | 退所日 | 任意 | `2026-05-31` | 退所日。現在入所中なら空欄 |
| 期間 | 最終確認日 | 自動 | `2026-05-31` | CSV上で最後に確認できた日 |
| 期間 | 初回不在日 | 自動 | `2026-06-01` | CSVから初めて消えた日 |
| 状態 | 現在入所中 | 自動 | `true/false` | 最新CSVに存在するか |
| 場所 | 入所フロア | 必須 | `2F` | 入所時または主たる入所フロア |
| 場所 | 最新フロア | 自動 | `3F` | 最新CSV上のフロア |
| 場所 | 部屋 | 自動 | `200` | 最新CSV上の部屋 |
| 場所 | Bed | 自動 | `01` | 最新CSV上のBed |
| 区分 | 入所形態 | 自動 | `長期` / `短期` | 毎日CSVの `形態` |
| 流入 | 流入元種別 | 手入力 | `病院` | 病院、居宅、包括、家族、法人内、その他、不明 |
| 流入 | 流入元名称 | 手入力 | `A病院` | 具体的な病院名、居宅名など |
| 流出 | 退所先 | 退所者のみ手入力 | `自宅` | 自宅、病院、特養、有料、死亡、その他、不明 |
| 流出 | 退所理由 | 退所者のみ手入力 | `在宅復帰` | 粗い分類でよい |
| 派生 | 滞在日数 | 自動 | `130` | 入所日から退所日または基準日までの日数 |
| 派生 | 入所回数 | 自動 | `2` | 同一利用者IDの何回目の入所か |
| 派生 | 再入所フラグ | 自動 | `true/false` | 入所回数が2以上ならtrue |
| 派生 | 前回退所日 | 自動 | `2025-06-20` | 同一利用者の前回エピソード退所日 |
| 派生 | 再入所までの日数 | 自動 | `77` | 前回退所日から今回入所日までの日数 |
| 補足 | メモ | 任意 | テキスト | 手入力補足 |

### エピソードIDの作り方

初期案:

```text
E_{利用者ID}_{入所日}
```

例:

```text
E_00140931_20250122
```

同じ利用者が同じ日に複数回入所するケースは通常想定しない。もし将来必要になれば連番を追加する。

### 入所エピソードテーブルで見えること

- 年間の延べ入所回数
- 入所者の実人数
- 同じ人の再入所
- 滞在期間
- フロア別の滞在傾向
- 退所後に戻ってきた人
- 短期反復利用者
- 長期入所化している人
- 流入元別の入所件数
- 退所先別の退所件数
- 退所理由別の退所件数

## 3. フロア定員テーブル

フロア別の概算利用率を出すために持つ。

| 項目 | 必須 | 型・例 | 内容 |
|---|---:|---|---|
| フロア | 必須 | `2F` | 2F、3F、ユニット |
| 定員 | 必須 | `40` | そのフロアの定員 |

初期値例:

```csv
フロア,定員
2F,40
3F,40
ユニット,20
```

## 毎日CSVから自動で埋まる項目

毎日出力される入所者一覧CSVを使う。

例:

```text
患者一覧_入所（アルボース医師）_20260531.csv
```

確認済みのCSV列:

```csv
指示確認,ｵｰﾀﾞｰ,部屋,Bed,1号,患者ID,入院日,退院予定日,氏名,カナ氏名,年齢,性別,日数,形態,検査,薬,主治医,看護師,相談員,カルテ記載
```

このCSVから自動で埋められる項目は以下。

| DB項目 | CSV列・作成方法 |
|---|---|
| 利用者ID | `患者ID` |
| 入所日 | `入院日` |
| 入所形態 | `形態` |
| 部屋 | `部屋` |
| Bed | `Bed` |
| 入所フロア・最新フロア | `部屋` から判定 |
| 現在入所中 | 最新CSVに存在するか |
| 最終確認日 | その利用者が最後にCSVにいた日 |
| 初回不在日 | その利用者が初めてCSVから消えた日 |
| 退所日 | 初期設定では `最終確認日` を退所日推定として使う |
| 滞在日数 | `入所日` と退所日または基準日から計算 |
| 入所回数 | 同一利用者IDのエピソード数から計算 |
| 再入所フラグ | 入所回数が2以上か |
| 再入所までの日数 | 前回退所日と今回入所日から計算 |

## 毎日CSVからは自動で埋まらない項目

以下は毎日CSVには存在しないため、手入力または別データ連携が必要。

| DB項目 | 入力方法 | 内容 |
|---|---|---|
| 流入元種別 | 手入力 | 病院、居宅、包括、家族、法人内、その他、不明 |
| 流入元名称 | 手入力 | 具体的な病院名、居宅名など |
| 退所先 | 手入力 | 自宅、病院、特養、有料、死亡、その他、不明 |
| 退所理由 | 手入力 | 在宅復帰、医療的理由・入院、他施設移行、家族・本人希望、死亡、その他、不明 |
| メモ | 任意 | 分析に必要な補足 |

手入力は、最初から全員分を完璧に埋める必要はない。

まずは、退所者・再入所者・気になる流入元のケースから補足する。

## フロア判定ルール

`部屋` の値からフロアを判定する。

| 部屋の形式 | フロア |
|---|---|
| `2xx` | 2F |
| `3xx` | 3F |
| `U-*` | ユニット |
| その他 | 不明 |

例:

```text
200 -> 2F
302 -> 3F
U-1 -> ユニット
```

## 入所・退所・再入所の扱い

### 入所

CSVに新しく出現した利用者を入所候補として扱う。

ただし、入所日はCSV内の `入院日` を正とする。

### 退所

前回CSVに存在し、今回CSVに存在しない利用者を退所候補として扱う。

退所日は厳密にはCSVだけでは確定できないため、以下を両方持つ。

| 項目 | 意味 |
|---|---|
| 最終確認日 | 最後にCSV上で確認できた日 |
| 初回不在日 | 初めてCSVから消えた日 |

初期分析では、退所日を `最終確認日` として扱う。

### 予定表Excel・変更CSVとの照合

ユニット、2F、3Fなどの予定表Excelや、そこから出力された変更箇所CSVは、入退所・転床予定、送迎、時刻、場所、備考を補う補助データとして扱う。

ただし、これらは手入力の運用表なので、氏名や漢字が表記ゆれ・誤記を含む可能性がある。

照合時の正本は、患者IDを持つ毎日CSV、および毎日CSVから作成した `daily_residents` / `episodes` とする。

Excel側の氏名が毎日CSVの氏名と一致しない場合でも、同じ日付のフロア入退所境界が一意に一致する場合は、氏名表記ゆれ候補として別ステータスで保持する。Excel氏名で毎日CSVの氏名や患者IDを上書きしない。

### 再入所

同じ利用者IDが過去に退所済みエピソードを持ち、その後再びCSVに出現した場合、再入所として扱う。

同じ人が再入所した場合、過去行は上書きせず、新しいエピソード行を追加する。

## 入力対象範囲

初期分析では、以下を対象にする。

> 現在入所中の全員と、直近4か月以内に退所した入所者を入力対象にする。入所日が4か月より前でも、現在入所中または直近4か月内に退所していれば対象にする。

毎日CSVを蓄積できる場合は、1年分を取り込む。

1年分を取り込む理由:

- 現在入所中の人には、1年以上前から入所している人がいる
- 1年単位で見ないと、再入所や短期反復利用が見えにくい
- 月別入所・退所の季節性や偏りが見えない

## 退所理由の分類

退所理由は、初期では細かくしすぎない。

分類は以下で十分。

```text
在宅復帰
医療的理由・入院
他施設移行
家族・本人希望
死亡
その他
不明
```

退所先は以下を基本にする。

```text
自宅
病院
特養
有料
死亡
その他
不明
```

流入元種別は以下を基本にする。

```text
病院
居宅
包括
家族
法人内
その他
不明
```

## 初期では入れない項目

以下は初回データベースには入れない。

- 氏名
- カナ氏名
- 担当者
- 要介護度
- 医療依存度
- 次アクション
- ロングステイ提案可能性

理由:

- 入力負荷が増える
- 個人情報リスクが増える
- 担当者別分析は個人評価に見えるリスクがある
- 最初の目的は、流入・滞在・流出の構造を見ることだから

ただし、毎日CSVに含まれる `相談員` は、将来の分析用に内部保持してもよい。初回の見せ方には使わない。

## 出したい示唆と必要データの対応

| 出したい示唆 | 必要データ |
|---|---|
| 月別の入所数 | 入所エピソードの入所日 |
| 月別の退所数 | 入所エピソードの退所日 |
| フロア別の在所者数 | 入所日、退所日、フロア |
| フロア別の概算利用率 | フロア別在所者数、フロア定員 |
| 流入元別の件数 | 流入元種別、流入元名称 |
| 退所先別の件数 | 退所先 |
| 退所理由別の件数 | 退所理由 |
| 長期入所者と短期退所者の分布 | 入所日、退所日、滞在日数 |
| 年間の延べ入所回数 | エピソードID |
| 実人数と延べ人数の違い | 利用者ID、エピソードID |
| 再入所者の数 | 利用者ID、入所回数 |
| 再入所までの日数 | 前回退所日、今回入所日 |
| 退所後に戻ってきている人 | 利用者ID、複数エピソード |
| 病院退所後に再入所している人 | 退所先、再入所フラグ |
| 自宅退所後に再利用できている人 | 退所先、再入所フラグ |
| 特定の流入元から再入所につながっているか | 流入元名称、再入所フラグ |
| フロア別の滞在期間 | フロア、滞在日数 |
| 長期入所化している人 | 滞在日数、現在入所中 |
| 短期反復利用の人 | 利用者ID、複数短期エピソード |

## 初期MVPの完成条件

まずは、以下が作れればよい。

1. 毎日CSVから利用者ID、入所日、フロア、入所形態、現在入所中、退所日推定を自動で作れる
2. 同じ利用者IDの複数入所を、複数エピソードとして保持できる
3. 流入元種別、流入元名称、退所先、退所理由を手入力で補足できる
4. フロア定員を別表で持てる
5. 上記データから、年間タイムライン、月別入退所、フロア別利用率、再入所者リストを作れる

## 実装時の注意

- CSV文字コードは `CP932` を優先して読む
- ファイル名の日付からスナップショット日を取得する
- `患者ID` と `入院日` が空欄の行は除外する
- 氏名・カナ氏名は分析用出力に含めない
- `退院予定日` は参考情報であり、退所日とは扱わない
- `退院予定日` に `2026/05/31(確)` のような文字が混じる場合、日付部分だけ抽出する
- 日次CSVが欠ける日があると退所日推定に誤差が出るため、最終確認日と初回不在日は必ず保持する
- 同じ人が再入所した場合、過去行は上書きしない
- 入所日が古くても、現在入所中なら必ず対象にする

## このデータベースで守るべきこと

最初から全情報を入れようとしない。

自動で取れる事実と、手入力が必要な判断情報を分ける。

自動で取れる事実:

- 誰が
- いつから
- どこに
- 長期か短期か
- いつまで在所していたか
- 再入所しているか

手入力が必要な判断情報:

- どこから来たか
- どこへ退所したか
- なぜ退所したか

この分離により、入力負荷を抑えながら、利用率低下を構造的に分析できるデータベースにする。
