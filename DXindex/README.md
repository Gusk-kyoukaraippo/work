## Excelランチャー版（追加設定なし）

カード形式の「DXアプリホーム.xlsx」と、進め方・進行状況を掲載する「DX活動ガイド.html」を作成しました。[配布一式](outputs/01a0c900-623e-71d2-9af0-a2392f990288/DXアプリホーム-配布一式.zip)と[使い方](excel-launcher/使い方.md)を参照してください。

ランチャーはVBA・追加EXE・レジストリ登録を使わず、表計算ソフトの標準ハイパーリンクを使います。ホームは3列、24件まで。登録用シートの名前・説明・分類・起動先・1文字のアイコンを変更すると表示へ反映され、未登録のカードは非表示になります。一言欄は初期状態で空欄です。初期登録の2アプリは職場のパスが未入力なので「準備中」です。

Windows／JUST Calcでマクロなし版が動作したとの利用者報告があります。ソフトの版と共有元のパスは実機で記録してください。以下の従来HTML＋Windows起動設定版も残しています。

生成は `npm run build:excel`。Node.jsは開発側だけで使います。Excel作成にはCodexの同梱 `@oai/artifact-tool` を使用し、`DX_WORKSPACE_NODE_MODULES`、`DX_PYTHON`、`DX_EXCEL_OUTPUT`で開発環境を指定できます。再生成は初期データのファイルを出力するため、運用中の登録済みブックを出力先に置かないでください。

PCの共有フォルダで使う、アプリへの入口とプロジェクト進捗の一覧です。画面は **`DXダッシュボード.html` 1ファイル**です。ブックをボタンから開く場合は、[Windows連携の配布一式](deliverables/DXダッシュボード-Windows連携.zip)に入った起動プログラムも各PCへ設定します。インターネット接続やサーバーの準備は不要です。スマートフォンは対象外です。

## 最初の設定

1. `DXダッシュボード.html` を、実際に使う共有フォルダへ置き、Edgeで開きます。
2. 「パスワードを設定」（右上の「初期設定」からも可）で内部メンバー共通のパスワードを設定します。4〜128文字です。初期パスワードはありません。
3. 管理画面の「アプリを登録」「プロジェクトを登録」から実際の内容を登録します。
4. 「更新したHTMLを出力」を押します。ダウンロード表示にファイルがあることを確認します。
5. ダウンロードしたHTMLで、共有フォルダの元ファイルを置き換えます。ブラウザが名前に「(1)」などを付けた場合は、元の名前に戻します。
6. 共有先のHTMLを開き直し、内容・相対リンク・内部向けパスワードを確認します。

初期データは空です。ソース内の初期HTMLや `npm run build` の出力も空の状態です。実データを登録した共有HTMLは、開発用の空HTMLとは別に管理してください。

## 日々の閲覧と更新

- 「DXアプリ一覧」では、アプリごとの「できること」を確認できます。HTMLは「アプリを開く」、Excelゲートなどのブックは「ブックを開く」から起動します。ブックの起動には各PCの初回設定が必要です。「開かないとき・初回設定」から案内を確認できます。
- 「プロジェクトの進行状況」では、プロジェクト名・現在の段階・状態・最近の進捗・進捗更新日を確認できます。
- 内部向け：「内部資料・管理画面を開く」から共通パスワードで解除すると、担当者・内部メモ・資料リンクを表示します。「アプリ・進捗を編集」から管理画面を開けます。
- 「外部向け表示に戻る」または再読み込みでロックします。パスワード・解除状態はブラウザに保存しません。
- 管理画面からアプリと案件の登録・編集・削除、パスワード変更ができます。内部メモや資料だけの変更では、外部に表示する「進捗更新日」は変わりません。
- 新規アプリの起動方式は「ブックから使う（Excelゲートなど）」が初期値です。HTMLを直接開く場合は起動方式を切り替えて登録します。既存のブック登録にもWindows起動リンクが適用され、既存のHTML起動は維持します。
- 編集内容はこの画面のメモリだけにあります。HTML出力やJSONバックアップを行う前に閉じると失われます。変更がある場合は、ブラウザの終了確認を表示します。
- ダウンロードしただけでは共有先は更新されません。HTMLを元の場所へ配置し、閲覧者が再読み込みして初めて反映されます。出力後も配置確認のため終了確認が出ます。
- 複数人の編集は自動統合しません。編集担当者を決め、最新の共有HTMLを開き直してから更新してください。

8段階は「困りごとの発見 → わけなぜシート作成 → インタビュー → わけなぜシート修正・アクションシート作成 → MVP作成 → miharaDB掲載 → ユーザー検証 → 実務実装」です。「進行中・保留・完了」は段階とは別に設定します。

## 相対リンクとExcel

例えば、次の配置で使えます。

```text
共有フォルダ/
├─ DXダッシュボード.html
├─ アプリ/
│  ├─ 申し送り.html
│  └─ 引継ぎメモ/
│     ├─ 引継ぎメモ.xlsm
│     ├─ gate.config.json
│     ├─ runtime/
│     └─ shared/  （ほかの同梱ファイルも一式で配置）
└─ 資料/
   └─ 現状分析.xlsx
```

| 対象 | 登録するリンク先 |
| --- | --- |
| HTMLアプリ | `./アプリ/申し送り.html` |
| Excelゲートのブック | `./アプリ/引継ぎメモ/引継ぎメモ.xlsm` |
| 内部資料 | `./資料/現状分析.xlsx` |
| 1階層上のフォルダ | `../別アプリ/操作パネル.xlsm` |
| Windows共有パス | `\\server\share\業務ツール.xlsm` |
| Webページ | `https://intranet.example/app` |

相対リンクの基準は、いま開いているダッシュボードの場所です。配置関係を保つとリンク先も追従しますが、Excelゲートの初回設定済みブックは登録済みの場所から動かさず、配置変更はMVP8thの導入手順に従います。ダウンロードフォルダにあるHTMLをそのまま開くと、相対リンク先はダウンロードフォルダ基準になります。

日本語、空白、`#`、`%` などを含むファイル名は、そのままパス欄へ入力できます。Windowsの「パスのコピー」で付く外側の引用符と前後の空白は除いて登録します。相対パス・Windowsパスの記号はファイル名として扱います。`http` / `https` URLのクエリやフラグメントはそのまま扱います。

### ExcelゲートMVP8thの登録と開き方

1. アプリの配布ZIPを展開し、フォルダ一式を共有先に配置します。ブックだけを取り出しません。初回設定はMVP8thの導入手順に沿って済ませます。
2. ダッシュボードの管理画面で、起動方式を「ブックから使う（Excelゲートなど）」にし、**配置済みのアプリ名.xlsm**のパスを登録します。共通原本 `workbook/MVP8th.xlsm` や `runtime` 内のHTMLは使いません。ZIP・HTML・フォルダはブックとして新規登録・変更できません。
3. 更新HTMLを正式な共有先へ配置します。既存HTMLから更新する場合はJSONバックアップを新版に復元してから出力し、元のアプリIDと登録内容を維持します。
4. 各PCで配布一式の `Windows起動設定/初回設定.cmd` を実行し、正式な共有先のHTMLを選びます。開くブックと起動する表計算ソフトを確認して「このPCに登録」を押します。ExcelゲートはJUST Calcで開く設定にします。
5. 利用者はカードの「ブックを開く」を押します。Windowsの起動プログラムが、登録済みの元ブックを開きます。Edgeの確認画面が出た場合は、内容を確認して開きます。パスのコピーは通常の操作には不要です。
6. CSV閲覧型はブックの「最新CSVで開く」、ブック保存型は「編集する」または「閲覧する」を押します。ブック保存型の正式保存は、Edgeの「入力を終える」→ブックの「保存して終了」→保存完了通知まで確認します。

具体的な初回設定、更新、解除、実機確認は [Windows起動設定の使い方](launcher/使い方.md) にあります。アプリの追加・ブックの場所の変更後は最新HTMLで各PCの登録も更新します。古い登録のまま違う場所を開くことはありません。名前・説明だけの変更ではPC設定の更新は不要です。

ダッシュボードは元ブックへの入口です。ブックのマクロ起動・業務データの保存はExcelゲートが担当します。登録済みの操作メモは内部向けを解除した人だけ開き方案内でも読めます。外部向けにはMVP8thの共通手順を表示します。従来のJSONはそのまま復元できます。誤った種類のリンクを含む旧JSONでも全体の復元を止めず、該当アプリを開いた時に登録修正を案内します。

MVP8thは初回設定時の正本パスと実際のブックの場所を照合します。Windowsの起動プログラムは元のブックをそのまま開き、ダウンロードやコピーを行いません。開かなかった場合は「開かないとき・初回設定」の案内を使います。手動で元パスをコピーする補助操作も使えます。ブックがダウンロードされる「直接リンクで開く」「通常のファイルリンクを試す」は廃止しました。

起動リンクは `dx-workbook://open/v1/アプリID/パス照合値` です。任意のコマンドや起動先をHTMLから渡す方式ではなく、PCに登録したブックだけが対象です。ブラウザは起動完了を検出できないため、「起動を要求しました」とだけ表示します。起動プログラムはWindows 10／11・.NET Framework 4.8以降が対象です。Macのローカル相対パスやWeb URLなどWindowsの元ブックを特定できない場合は、起動リンクを生成せず案内を表示します。

Edgeの外部アプリ起動の確認は、職場の設定によって表示されます。この配布物はEdgeのポリシーやマクロの設定を変更しません。`file://*` の確認省略には制約があるため、確認なしの1クリックは実機で確認します。[Edgeの設定条件](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/autolaunchprotocolsfromorigins)

Web URLを登録した場合、またはWeb上のダッシュボードから相対リンクを使った場合は、そのURLを共有ブックの保存場所とは扱わず、元ブックのパスの登録を案内します。Windows共有先を指す `\\server\share\...\アプリ名.xlsm` を登録してください。すべての利用者が同じ正本パスから開く運用にします。

導入前に、実際に開いたブックのフルパスが共有フォルダを指していることを確認してください。Edgeのダウンロード後の自動オープンは、共有元のブックを開く機能とは異なります。[Microsoftの説明](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/AutoOpenFileTypes)

イントラネットHTTPSからエクスプローラーを開くEdgeのポリシーは、対象サイト・Windows側の設定が必要で、このHTMLには含めません。[IntranetFileLinksEnabled](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/intranetfilelinksenabled)。拡張子ごとのJUST Calcの関連付けは [JustSystemsの案内](https://support.justsystems.com/faq/1032/app/servlet/qadoc?QID=058436) を参照できます。

## バックアップと復元

管理画面の「JSONバックアップ」で登録内容とパスワード検証設定を保存します。「JSONから復元」は内容を全件置き換えます。件数と出力日時を確認し、そのバックアップのパスワードを入力して実行してください。復元後は外部向けのロック状態に戻ります。共有へ反映するには改めてHTMLの出力・配置が必要です。

10MiBを超えるファイル、不正な形式、未対応バージョン、不正なリンクなどは拒否し、現在の登録内容を維持します。登録データ全体も10MiBまで、アプリ・プロジェクトは各1,000件まで、資料リンクは1案件30件までです。既存の進捗ボードや改善アプリのJSONは直接取り込めません。

簡易ロックのパスワードは、ランダムなソルトとSHA-256の検証値として保持します。HTML・バックアップ内の内部データ自体は暗号化されません。ファイルを調べたり変更したりできる人に対するアクセス制御にはなりません。パスワードは控えておき、忘れた場合はファイルを管理する担当者に再設定・再発行を依頼してください。パスワード文字列を復元する機能はありません。

## 対応環境と検証

- 対応対象：EdgeHTML 16以降と現在のMicrosoft Edge。IEおよびEdgeのIEモードは案内画面だけを表示します。
- ES5構文と旧Edgeで使えるAPIで構成しています。ファイル読み込みはFileReader、旧Edgeのダウンロードは `msSaveOrOpenBlob` を使います。ネイティブの `dialog`、`structuredClone`、`fetch`、外部ライブラリへの通信には依存しません。
- PC向けの表示です。推奨幅は1,280px以上、画面の最小幅は960pxです。さらに狭いウィンドウでは横スクロールで表示します。
- 本文・ボタンは基本18px、補足は16pxです。アプリカードは20件程度を想定し、名前20px・説明と起動ボタン16px、起動ボタンの高さ44px以上でコンパクトに表示します。画面幅1,200px以上で4列、1,600px以上で5列、それより狭いPC幅では3列です。名前と説明は省略しません。
- この環境で確認済み：macOS上のChromeでの操作、HTML・JSON往復、相対リンク先の実ファイル起動とフォルダ移動、PC画面表示、外部通信なし。
- Windows起動プログラム：Windows用EXEのビルド成功。HTMLからの起動リンク生成と、同一C#ソースのパス照合・登録読込・不正要求の拒否を自動確認。Windowsの登録画面・レジストリ登録・表計算ソフトの実起動は未実測。
- 未検証：Windowsの実機、旧Edgeの実エンジン、現在のEdge、IEの実エンジン、Windows共有フォルダからのJUST Calc／Excel起動とVBA。IE検出・旧Edge向け保存分岐のシミュレーションは実機検証を代替しません。

検証の詳細は [検証記録.md](検証記録.md) に記録しています。

## 開発用

通常利用時にNode.jsやnpmは不要です。以下はソース変更時だけ実行します。

```sh
npm ci
npm run build
npm test
```

`npm run build` は `src/shell.html`（スタイル内蔵）・JavaScriptと同梱ライブラリをまとめ、**空データの配布用HTMLを再生成します**。独立したCSSファイルはありません。HTMLのみでも一覧・編集・HTMLリンクは使えます。Windowsのブック起動には配布一式の起動設定を追加します。`src/shell.html` は開発用のテンプレートです。実データ入りの共有HTMLに対してビルドを実行しないでください。

起動プログラムの開発・配布には.NET SDK 10とPython 3を使います。`npm run test:launcher` はブラウザとC#の共通パス事例を検証し、`npm run package:windows` はWindows用EXEと配布フォルダ・ZIPを生成します。`DX_DOTNET`、`DX_PYTHON`で開発用実行ファイルを指定できます。Windows用EXEは.NET Framework 4.8を対象にし、利用者PCにSDKは不要です。`launcher/`がソースです。

ブラウザテストはmacOSのGoogle Chromeを既定で使います。別のChrome/Chromiumを使う場合は環境変数 `DX_CHROME_PATH` に実行ファイルを指定してください。出力先 `test-results/` のHTML・JSON・スクリーンショットは検証用サンプルであり、配布用ではありません。

JSONの識別子は `format: "dx-team-dashboard"`、`schemaVersion: 1` です。詳細は `src/core.js` の正規化処理とテストを参照してください。パスワードの検証形式は `sha256-salt-v1`（32桁の16進ソルトと64桁の16進ハッシュ）で、検証対象文字列は `dx-team-dashboard/v1`、改行、ソルト、改行、パスワードの順です。

SHA-256は [js-sha256 0.11.1](https://github.com/emn178/js-sha256)（MIT License）をHTML内に同梱しています。ライセンス文も生成HTML内に収録しています。

## 各段階の説明へのリンク

管理画面の「8段階の説明リンクを設定」で、各段階の説明ページの場所を登録します。外部向けにも「DX実装の8段階」内にリンクが表示され、案件には現在の段階の説明リンクも表示されます。内蔵説明文はリンク未登録でも読めます。外部の説明ページは任意の関連リンクとして追加できます。

同じHTMLの途中へリンクする場合は、説明ページの場所（例：`./資料/DXの進め方.html`）と、ページ内の見出しID（例：`step-2`）を別々に入力します。見出しIDには `#` を付けません。相対パスの `#` はファイル名の一部として扱います。Web URLは通常の `https://…#step-2` 形式でも指定できます。

設定後は「更新したHTMLを出力」し、共有先を置き換えてください。JSONバックアップにも設定を含みます。旧JSONでは説明リンクを未登録として復元します。第2〜4段階の名称は変更しましたが、既存案件の段階番号は変更しません。

## 内蔵した8段階の説明文

説明文はダッシュボードHTMLの中に含まれています。「DX実装の8段階」の各段階にある「詳しい説明」、または案件の「この段階の説明を読む」で表示します。外部メンバーも読めます。配布時に別の説明HTMLを用意する必要はありません。

現在の文章は仮案です。内部向けを解除し、管理画面の「8段階の説明文を編集」で段階を選んで修正してください。段階を切り替えながら編集でき、「説明文を保存」で全段階の変更を反映します。確定した文章では冒頭の仮案表示も削除してください。その後「更新したHTMLを出力」して共有先を置き換えます。説明文はJSONバックアップにも含まれ、説明文を持たない旧JSONには初期の仮案を補います。

## 常時表示する8段階の概要

画面は「DXアプリ一覧」→「DX実装の8段階」→「プロジェクトの進行状況」の順です。8段階の名称と短い説明はクリックせずに読めます。詳細な作業内容や完了の目安は「詳しい説明」で開きます。

管理画面の「8段階の説明文を編集」では、常時表示する短い説明（各240文字まで）と詳しい説明文をそれぞれ編集できます。どちらもHTML出力とJSONバックアップに含まれます。短い説明を持たない旧JSONには、初期の短い説明を補います。

画面の配色は参考の進捗ボードに合わせ、濃い緑・オレンジ・青を使っています。8段階は色付き番号と小さな工程アイコンで示し、進行中の段階をオレンジ、完了状態の最終表示を青で示します。ヒントカード、スローガン、励ます通知は表示しません。

アプリカードは白、起動ボタンはExcel・HTML共通の深緑です。カード上端の色線はありません。アイコン背景だけを淡い緑・青・紫・黄の4色にし、保存済みのアプリIDから固定的に割り当てます。名前変更・並べ替え・別アプリの追加・HTML出力・JSON復元では、同じIDの色は変わりません。色の設定項目や保存項目は追加せず、Excel側のテーマカラーとも同期しません。

8段階は4段階ずつ2行の工程表で表示します。前半・後半の見出しは置かず、余白を抑えています。各段階の説明や管理方法は共通です。
