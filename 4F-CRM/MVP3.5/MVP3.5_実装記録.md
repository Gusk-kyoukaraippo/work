# 4F BedFlow MVP3.5 実装記録

## 目的

MVP3の病床管理を維持しつつ、外来診察、外来リハ、不定期入院、定期入院に分かれていた情報を患者単位で俯瞰する「院内難病患者・包括管理台帳」を追加した。声掛けや空床活用は台帳の付随機能とし、将来はデイサービス、ショートステイ、訪問系・地域サービスまで同じ患者へ紐づけられる構造とした。診療録や介護記録そのものは複製しない。

## 追加したUI

- 第3タブ「難病患者台帳」を追加。1患者1行で疾患、外来・リハ、入院実績と予定、入院区分、病棟適応、担当部署を表示する。
- 入院歴のない外来・外来リハ患者を、CP重複と同名患者を確認しながら台帳へ直接追加できる。
- 疾患、利用形態の組み合わせ、定期／不定期、病棟適応、台帳状態、要確認条件で検索・絞り込みできる。50人単位でページ表示する。
- 患者詳細で複数疾患、元病名、サービス利用関係、入院区分、調整状態を編集し、直近24か月の外来・リハ・入退院・調整記録を同じ時系列に表示する。
- 台帳から既存の「次回日程・部屋調整」へ患者と性別を引き継ぐ。
- 空床期間と本日の外来実績、確認済み疾患、病棟適応あり、入院予定重複を照合する候補確認を追加した。自動スコアや診療上の優先順位付けは行わない。
- 正本JSONの保存ボタンを追加し、従来のJSON読込・端末内一時保存と併用できる。

## schema v5

既存の `patients / admissions / assignments / blocks / changeLogs` を維持し、次を追加した。

- `patientDiseases`：院内8疾患区分、元病名、確認待ち／確認済み／終了。
- `serviceCatalog`：外来、外来リハ、入院と、将来利用する介護・地域サービスの定義。
- `patientServiceRelations`：利用中／休止／終了、事業所、頻度、担当部署。
- `serviceEvents`：取得できた外来・リハの実績、予約、取消。
- `admissionProfiles`：定期／不定期／未確認、利用間隔目安、病棟適応、調整状態。
- `coordinationRecords`：部署間確認、声掛け、入院調整、地域連携の最小限の履歴。

`patients`には正式／仮／未確認CPと、利用中／休止／アーカイブ状態を補足できる。`settings.registry`には履歴表示期間、アーカイブ目安、部署候補を持つ。schema v4読込時は不足配列と既定サービスを補完するが、旧 `patients.regular` から定期入院を自動確定しない。

## MVP3との互換性

- MVP3rdは変更せず、MVP3.5を別フォルダ・別HTML・別ブラウザ保存キー `bedflow-4f-working-data-v35` とした。
- MVP3の保存キーからは初回だけコピーしてv5へ正規化する。
- 病床ボード、配置待ち、予定移動、転床、重複・男女・整備時間の警告、次回日程・部屋調整、相談からの配置待ち登録を維持した。
- v5の追加情報は既存入院配列を置き換えず、正式な患者照合は `patientId` とCP確認を介して行う。

## 予約未連携の扱い

CSV列と予約出力方式は固定していない。取得できた予約は `serviceEvents` の予定として扱い、取得口が決まるまでは必要な範囲で手入力できる。サービス定義が未連携の場合、未来予定がなくても「予約なし」と断定せず「予約情報未連携」と表示する。連携済みと明示された場合だけ「次回予約なし」と表示する。

## 患者統合とアーカイブ

- CP重複は通常編集で拒否し、仮CP・重複患者は確認操作を経て正式患者へ統合する。
- 統合時は入院、疾患、サービス関係、イベント、入院区分、調整記録の患者参照を付け替え、疾患・サービスの明確な重複を整理する。
- 入院と外来・リハ実績に完全一致する重複候補がある場合は削除せず、統合元のアーカイブへ確認待ちとして残し、正式患者の利用回数へ二重計上しない。
- 統合元患者は削除せず、統合先ID、アーカイブ日時、年度を残して通常一覧から外す。
- 診療終了・休止・アーカイブは台帳状態として切り替え、必要時に絞り込み表示できる。現版では年度別ファイルへの自動分割は行わない。

## テスト

Node.js標準ライブラリだけで静的回帰テストを実行できる。

```sh
node MVP3.5/tests/run-static-tests.mjs
```

実行結果は **27件成功、0件失敗**。HTML内JavaScript構文、外部通信非依存、DOM参照、3タブ操作、MVP3主要機能、台帳主要機能、外来のみ患者の新規登録、日程調整時の性別未確認処理、空床候補の必須条件、動的編集欄のアクセシビリティ、schema v5配列、サンプルJSONのID・CP・患者／入院／病床／サービス参照と日時整合性を確認した。ブラウザで行う回帰・受入確認は `tests/README.md` に記載した。

## 現時点の制約

- 外来・リハCSVの列、取込単位、重複判定、予約取込方式は実サンプル確認後に決める。現版にCSV取込処理はない。
- 正本JSONは院内共有場所で1ファイルを排他運用する前提。ブラウザ内保存は端末単位の一時保存であり、同時編集の自動調停はしない。
- 本台帳は診療継続、患者把握、部門間調整を支援するもので、電子カルテ、部門システム、研究レジストリの代替ではない。
- 疾患確定、入院区分、病棟適応、実際の入院可否は職員が確認する。自動診断、自動優先順位付け、自動連絡は行わない。
