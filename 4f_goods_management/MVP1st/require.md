## 📋 要件定義

### 🎯 プロジェクト概要

院内の物品をQRコードで管理するシステム。**MVP対象はノートPC 10台**だが、将来的には機器種別・台数の拡張を前提とした設計とする。スマホでQRを読み取るだけで所在・確認者を記録し、紛失・放置を防ぐ。ローカル動作から始め、最終的にGoogle Cloud上へ移行する。

---

### 👤 ユーザーと利用シーン

| **ユーザー** | **操作** |
| --- | --- |
| スタッフ（一般） | スマホでQRスキャン → 場所・氏名を入力（スキップ可） |
| 管理者 | 一覧確認・機器登録・QRコード生成・警告対応 |

---

### 📦 管理対象

- **MVP：** ノートPC 10台
- **将来：** 機器の種別・台数を追加可能な拡張設計
- 各機器にQRコードシールを貼付
- QRコード上に機器の識別名（例：「PC1」「タブレット3」等）を**目視用テキストとして印字**

#### 機器データモデル（拡張設計）

| **フィールド** | **内容** | **備考** |
| --- | --- | --- |
| 機器ID | システム内部のユニークID | 自動採番（UUID等） |
| 機器種別 | ノートPC / タブレット / 輸液ポンプ 等 | 自由に追加可能 |
| 表示名 | 「PC-01」「タブレット」等 | 通し番号なしも可（自由記述） |
| 備考 | 機器固有のメモ | 任意 |

> 通し番号は**必須ではない**。種別によって「タブレット（番号なし）」のような登録も可能とする。
> 

---

### ⚙️ 機能要件

#### F-01｜QRコードスキャン（チェック記録）

- スマホのカメラでQRコードを読み取る
- 読み取り後、以下の情報を記録する
    - 機器ID（QRから自動取得）
    - **見かけた場所**（テキスト入力 or プリセット選択）→ **スキップ可**
    - **確認者名**（テキスト入力）→ **スキップ可**
    - タイムスタンプ（自動）

#### F-02｜機器一覧・状態表示

- 登録済み全機器の一覧を表示
- **機器種別でフィルタリング・グループ表示**が可能
- 各機器に対して以下を表示
    - 表示名・機器種別
    - 最終確認日時・場所・確認者
    - **最終チェックから1週間以上経過している場合は警告表示**（例：赤色バッジ）

#### F-03｜機器登録・管理

- 管理画面から機器種別・表示名を自由に登録・編集・削除できる
- 機器種別は事前定義不要（その場で新規作成可能）
- 通し番号は任意（付けなくてもよい）

#### F-04｜QRコード生成

- 登録済み機器のQRコードを生成
- QRコードに表示名を併記し、印刷可能な形式で出力
- 複数機器を一括印刷できることが望ましい

#### F-05｜チェック履歴閲覧

- 各機器のスキャン履歴を時系列で確認できる

### 🛠️ 技術要件

| **項目** | **MVP（ローカル）** | **本番（GCloud）** |
| --- | --- | --- |
| フロントエンド | 単一HTML + JS（LocalStorage） | 同左 or 軽量フレームワーク |
| バックエンド | 不要（ブラウザのみ） | Cloud Run or Firebase |
| データ保存 | LocalStorage or JSON | Firestore or Cloud SQL |
| QRスキャン | スマホブラウザのカメラAPI | 同左 |
| QR生成 | JSライブラリ（qrcode.js等） | 同左 |

> **拡張性の担保：** 機器種別・台数はハードコードせず、データとして管理する。MVPのLocalStorageでも種別・台数を動的に増減できる構造にする。
>

### ✅ 受け入れ条件（MVP）

- [ ]  スマホブラウザでQRを読み取り、チェック記録が保存される
- [ ]  場所・確認者はスキップしてもエラーにならない
- [ ]  一覧画面で全登録機器の最終確認状況が一目でわかる
- [ ]  1週間未確認の機器に警告が表示される
- [ ]  QRコード（表示名付き）を生成・印刷できる
- [ ]  機器種別・台数を管理画面から自由に追加・変更できる
- [ ]  通し番号なしの機器も登録できる
