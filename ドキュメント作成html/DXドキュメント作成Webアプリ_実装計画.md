# DXドキュメント作成Webアプリ実装計画

## 概要

CSSとJavaScriptを内包した単一の `index.html` で、以下の資料を編集・相互参照・JSON保存・印刷できるWebアプリを作成する。

- Toyota A3改善シート
- 2種類のステークホルダー表
- 4カード構成のインセプションデッキ

外部ライブラリ、サーバー、IndexedDB、File System Access API、localStorageは使用しない。

## 画面と基本操作

- 起動時に「保存されたプロジェクトから再開」と「新規プロジェクト」の2択を表示する。
- 再開画面では、JSONのドラッグ＆ドロップとファイル選択に対応する。
- 新規作成時はプロジェクト名を必須入力とし、作成日を自動設定する。
- 作業画面には資料切替、JSON保存、印刷、資料参照、未保存状態を表示する。
- 記入欄やカードをクリックすると、画面右側約40～50%に編集パネルを開く。
- 「確定」でキャンバスへ反映し、「キャンセル」で編集前へ戻す。
- 未保存の変更がある状態でページを閉じる場合は警告する。
- 小画面ではキャンバスを横スクロール可能にし、編集パネルを全画面表示する。

## Markdown-lite編集

- 長文の記入欄は、リッチテキストではなくMarkdown-lite形式で保存する。
- 編集パネルは大きなテキスト入力欄と「入力／プレビュー」切替を持つ。
- A3全体画面、参照画面、印刷画面ではMarkdownを整形して表示する。
- 対応する記法を以下に限定する。
  - `#`、`##`、`###` による見出し
  - `-` による箇条書き
  - `1.` による番号付きリスト
  - `**文字**` による太字
  - `[表示名](URL)` によるリンク
  - 通常の段落と改行
- 表、画像、コードブロック、生HTML、JavaScriptはMarkdownとして処理しない。
- JSONには変換後のHTMLではなくMarkdown原文を保存する。
- リンクは `http:` と `https:` だけを許可し、危険なURLは通常の文字列として表示する。
- ステークホルダー表、トレードオフスライダー、日付などはMarkdownではなく専用入力UIを使用する。

## 資料間の相互参照

- 編集中の資料とは別の資料を、読み取り専用の縮小参照パネルで同時表示する。
- 参照パネルは資料切替、拡大縮小、折りたたみに対応する。
- 任意で参照資料を別ウィンドウへ開けるようにする。
- 別ウィンドウは単一HTMLから生成し、元画面から `postMessage` で最新内容を反映する。
- ポップアップが禁止された場合はエラーを表示し、画面内参照を継続して利用できるようにする。

## A3改善シート

A3横キャンバス内に、中央の印刷分割線をまたがない形で以下を配置する。

- プロジェクト名
- 担当者
- 作成日
- お困りごと（困っていること、選定理由を記入）
- 層別解析（Where）
- 目標値の設定（KGI）
- なぜなぜ分析・真因（Why）
- 対策案・実行スケジュール（How / KPI）
- 効果確認・標準化・再改善（Check / Act）

各記入欄をクリックすると、その欄のMarkdown-lite編集画面を右側に表示する。

- 通常はA4左ページに1・2、右ページに3〜6を配置する。
- 右ページの記入量が多く、左ページに余裕がある場合は、項目順を保ったまま3を左ページへ自動移動する。
- 各ページ内ではMarkdownの文字数と行数に応じて欄の高さを自動配分する。
- 自動調整後も収まらない場合は、はみ出し警告と欄ごとの文字倍率調整を使用する。

## ステークホルダー表

人物を内部の共通IDで管理し、表1と表2を連動させる。

### 表1

以下の列を持つ。

| 列 | 入力形式 |
|---|---|
| 人の名前 | 1行テキスト |
| 重要度 | 自由入力 |
| 影響度 | 自由入力 |
| 関心度 | 自由入力 |
| 関わり方 | 複数行テキスト |

- 重要度、影響度、関心度は選択式にせず、文字または数値を自由に入力できるようにする。
- 人物の追加、編集、削除、並べ替えに対応する。
- 「人物を追加」は表1上部の目立つボタンとして配置する。
- 「関わり方」はMarkdownを使用せず、単純な複数行テキストとして扱う。

### 表2

以下の列を持つ。

| 列 | 入力形式 |
|---|---|
| 人の名前 | 表1から自動反映 |
| 重要度 | 表1から自動反映 |
| 求める価値 | 複数項目 |

- 表2では名前と重要度を直接編集できないようにする。
- 表1の名前または重要度を変更すると表2へ即時反映する。
- 「求める価値」は人物ごとに項目を追加・削除・並べ替えできるようにする。
- 求める価値の各項目は短いプレーンテキストとして保存する。
- 表2は表1より本文文字を大きくし、「求める価値」を項目ごとの読みやすいブロックで強調表示する。
- 人物を削除する場合は、その人物に登録された「求める価値」も削除されることを確認ダイアログで通知する。

## インセプションデッキ

以下の4種類を1つのA3横キャンバス上にカードとして配置する。

### なぜここにいるのか

- Markdown-liteで目的、背景、解決したい課題を記入する。

### エレベーターピッチ

以下の定型項目を持つ。

- 対象顧客
- 顧客の課題
- 製品・サービス
- 提供する価値
- 代替手段
- 主な差別化要因

### やること／やらないことリスト

- 「やること」と「やらないこと」の2列で表示する。
- 各列で項目の追加、削除、並べ替えを可能にする。
- 各項目はプレーンテキストとして保存する。

### トレードオフスライダー

- スライダー項目の追加、削除、並べ替えに対応する。
- 各項目は左側の価値名、右側の価値名、現在位置を持つ。
- スライダー位置はキーボードとポインター操作の両方で変更できるようにする。

## JSON設計と保存

JSONには以下を保存する。

```json
{
  "schemaVersion": 1,
  "app": "dx-document-studio",
  "project": {
    "name": "プロジェクト名",
    "createdAt": "ISO 8601日時",
    "updatedAt": "ISO 8601日時"
  },
  "documents": {
    "a3": {},
    "stakeholders": {
      "people": []
    },
    "inceptionDeck": {}
  },
  "printSettings": {}
}
```

- Markdown欄にはMarkdown原文を保存する。
- ステークホルダーは人物ID、表1の情報、求める価値の配列を同じ人物オブジェクトに保持する。
- JSON読み込み時に形式、必須項目、型、バージョンを検証する。
- 不正なJSONの場合は現在のプロジェクトを変更せず、日本語のエラーを表示する。
- 未知の余剰プロパティは読み飛ばし、必須データの欠落や不正な型はエラーとする。
- 読み込み後も元のJSONファイルは変更せず、新しいファイルとして保存する。
- 保存にはBlobとダウンロードリンクを使用する。
- ファイル名はローカル日付を用いて次の形式とする。

```text
YYYYMMDD_HHmm_プロジェクト名_DXドキュメント.json
```

- ファイル名に使用できない文字は `_` に置換する。
- 編集データはメモリだけに保持し、自動保存は行わない。

## 印刷用補正

- 各資料を420×297mm相当のA3横キャンバスとして構成する。
- 中央で左右に分割し、左半分と右半分をA4縦1枚ずつ、合計2ページで印刷する。
- ステークホルダー表は表1を左側、表2を右側に配置し、印刷分割で表が切れないようにする。
- インセプションデッキは4カードを配置したキャンバス全体を左右に分割する。
- 印刷用補正モードで以下を調整できるようにする。
  - 資料全体の文字倍率
  - 欄ごとの文字倍率
  - 行間
  - 欄の内側余白
  - 空欄ガイドの表示・非表示
  - 印刷余白
- 印刷プレビューにA4境界線、左右ページ番号、文字のはみ出し警告を表示する。
- 実印刷では編集ボタン、ナビゲーション、境界ガイド、警告表示を非表示にする。
- `@page { size: A4 portrait; }` と印刷専用DOM/CSSを使用する。

## デザイン

- 白を基調に、柔らかなグレーと青系アクセントを使ったモダンで軽快な画面にする。
- 日常の編集画面は余白と読みやすさを優先する。
- 印刷時は背景色を抑え、白黒印刷でも構造を識別できる罫線と見出しを使用する。
- Toyotaのロゴや公式帳票デザインは使用せず、一般的な改善A3を基にした独自デザインとする。
- ボタン、入力欄、ダイアログにキーボード操作と視認可能なフォーカス表示を用意する。

## テスト計画

- 新規作成、JSON読み込み、3資料の編集、確定、キャンセル、資料切替を確認する。
- Markdown-liteの対応記法が全体画面、参照画面、印刷画面で同じように表示されることを確認する。
- 生HTMLや危険なリンクが実行されないことを確認する。
- 表1の人物追加、編集、削除、並べ替えが表2へ正しく同期されることを確認する。
- 名前や重要度を変更しても「求める価値」が同じ人物IDに保持されることを確認する。
- 複数の「求める価値」の追加、削除、並べ替えを確認する。
- 人物削除時の確認と、表1・表2からの同時削除を確認する。
- インセプションデッキのリスト操作とスライダー操作を確認する。
- JSON出力後に再読み込みし、すべての内容と印刷設定が復元されることを確認する。
- 破損JSON、異なる形式、未対応バージョンを安全に拒否できることを確認する。
- 未保存警告と、JSON保存後の警告解除を確認する。
- 参照パネルと別ウィンドウへ最新内容が反映されることを確認する。
- 3資料すべてがA4縦2ページとなり、表やカードが中央で欠けないことを印刷プレビューとPDF出力で確認する。
- Chrome、Edge、Safari、Firefoxで、ローカルの `index.html` を直接開いて主要操作を確認する。

## 対象外と前提

- 初期版は日本語・デスクトップ利用を中心とする。
- 外部画像、画像貼り付け、添付ファイルには対応しない。
- クラウド保存、自動保存、共同編集、ユーザー認証には対応しない。
- 外部CDNやWebフォントを使用せず、オフラインで動作可能にする。
- 成果物は外部ファイルを必要としない単一の `index.html` とする。
