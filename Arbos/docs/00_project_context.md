# アルボース改善プロジェクト Context

## この文書の位置づけ

この文書は、アルボースに関するデータ、分析、レポート、現場向けDX施策が「何のために存在するのか」を整理するための親文書である。

個別のCSV、SQLite DB、分析レポート、現場DX検討メモ、内部検証用リストは、それぞれ単独で見ると散らばって見える。ここでは、それらを以下の流れでつなぐ。

```text
老健全体の改善
  -> 喫緊テーマとしての病床利用率低下
  -> 利用者単位の追跡とフォロー
  -> 経営層向け報告
  -> 現場DXテーマの設計
  -> 継続的な改善サイクル
```

## コンサルとしての立ち位置

自分の主所属は別施設であり、アルボース専任ではない。

ただし、今後の目標は、もともと所属している施設の改善と、アルボースを含む老健領域のコンサルティングを同時に進めていくことである。

そのため、アルボースでの取り組みは、単発の資料作成やデータ集計ではなく、老健全体を改善していくための継続的なコンサルティングの入口として位置づける。

## 上位目標

上位目標は、アルボースを含む老健全体の経営・運営改善である。

改善対象は病床利用率だけではない。内部運用、現場負担、情報共有、顧客管理、経営判断の精度など、改善すべき点は多数ある。

ただし、初回テーマとしては、喫緊の課題である **病床利用率の低下** に焦点を当てる。

## 初回テーマ: 病床利用率低下への対応

初回で扱うテーマは、アルボースの病床利用率低下である。

目的は、単に利用率の数字を報告することではない。病床利用率が下がっている背景を、利用者単位の動きとして追跡し、どの利用者層に、どのタイミングで、どのようなフォローを行えば改善につながるかを判断できる状態にすることである。

現時点では、病床利用率低下への対応を、以下のように捉える。

- 経営層には、利用率低下の構造と優先すべき打ち手を示す
- 現場DXについては、個人情報を含まない範囲で候補テーマと業務課題を示す
- 分析担当側では、どの仮説が当たり、どの条件を修正すべきかを追跡する

## これまでの見方との違い

これまでは、主に純粋な病床数や利用率の集計で状況を見ていた。

今回の取り組みでは、利用者を追跡し、入所・ショート・デイ・退所後の動きをつなげて見ることで、単なる病床数の把握を超えた分析ができるようになっている。

この価値を明確に示す必要がある。

具体的には、以下の違いがある。

| 従来の見方 | 今回の見方 |
|---|---|
| 病床数・利用率を見る | 利用者単位の動きを追う |
| 空床が何床あるかを見る | どの利用者層で埋められる可能性があるかを見る |
| 月次・日次の集計で終わる | 次の確認設計・現場DX候補に落とす |
| 原因を大まかに推測する | ショート、ロング、デイ、退所後フォローに分解する |
| 経営層向けの報告で止まる | 現場DXの設計案へ接続する |

重要なのは、「データがある」ことではなく、データによって **次の打ち手を決められる** ことである。

## コンサルの大きな方向性

アルボース改善プロジェクトは、次の2本建てで進める。

### 1. 経営層向けの定期報告

経営層向けには、定期的にレポートを出す。

理想は、レポートを読んだ経営層が、細かい前提確認に時間を使わず、次のように受け止められる状態である。

> 状況は分かった。打ち手も分かった。次回もこの形で報告してほしい。

そのため、経営層向けレポートでは、単なる数字の羅列ではなく、以下を一体で示す。

- 現状
- 前回からの変化
- 主要な原因仮説
- 優先すべき打ち手
- 現場DXの検討状況
- 次段階で確認する論点

初回は病床利用率を扱うが、将来的には病床利用率だけでなく、老健全体の経営・運営に関する報告へ広げていく。

### 2. 現場向けのDX施策

経営層向け報告だけでは、現場の行動は変わりにくい。

そのため、経営層向けレポートとは別に、現場DX施策を並行して検討する。

現場向けDXの目的は、現場に新しい負担を増やすことではない。既存データを使って、どのような現場改善が可能かを見える化し、運用できる形に落とすことである。

ただし初回時点では、個人情報の取り扱い、現場配布の可否、現場向けCSVの有無、運用頻度、次回レポートの評価指標は未確定である。

そのため、初回の現場DXは、確定した現場配布物ではなく、検討中の改善テーマ、設計案、個人情報なしの集計として扱う。

## 現場DX施策の扱い

現場DXは本プロジェクトの重要テーマであるが、初回時点では、具体的な出力形式・配布範囲・運用頻度は未確定である。

特に、利用者名・利用者ID・担当者名などの個人情報を含む現場向けCSVについては、個人情報の取り扱い、閲覧権限、配布先、運用責任者が確定するまで、現場配布しない。

そのため、初回成果物では、現場DXを以下のように扱う。

1. 経営層向け本編では、現場DXの必要性と候補テーマを示す
2. 個人情報を含まない範囲で、対象者数・区分別件数・業務課題を示す
3. 個人情報を含む候補者リストは、分析担当または管理者限定の内部検証用とする
4. 現場配布用CSVは、個人情報取扱と運用ルールが確定した後に作成する
5. 週次・月次などの運用頻度は、初回時点では仮案とし、経営層・管理職・現場と協議して決定する

したがって、初回時点では「今週誰に当たるか」を現場へ直接提示することを確約しない。
まずは、利用者追跡データによってどのような現場DXが可能かを示し、次に配布範囲・頻度・責任者・記録方法を決める。

## 裏側にある中長期構想

表向きには、病床利用率低下への対応や、現場の困りごとを解決する小さなDX施策として進める。

一方で、中長期的には、これらの現場DXを積み上げて、顧客CRMまたはSEPのような仕組みに育てていくことを構想している。

さらに、そのCRM/SEP構想は、将来的にWindows環境のPower BIやAzureに落とし込んでいくことも視野に入れる。

ここで目指すのは、単なる名簿管理ではない。利用者、家族、ケアマネ、紹介元、利用履歴、フォロー履歴、次回確認日、相談状況、予約状況、再利用可能性などを、現場が実際に使える粒度でつなぐことである。

そのため、初期の現場DX施策は、それぞれ単独の便利ツールとして終わらせない。将来のCRM/SEP基盤に必要な部品として位置づける。

初期段階では、CSV、SQLite、簡易レポート、手入力テンプレートで小さく検証する。そこで固まったデータ項目、業務フロー、レポートの型、権限や運用の考え方を、将来的にPower BIやAzure上の仕組みに移していく。

| 現場DX施策 | 将来のCRM/SEPにつながる要素 |
|---|---|
| 重点フォロー候補 | 将来的な優先度設計・顧客スコアリング候補 |
| 退所後フォロー | 退所後接点、再利用可能性、次回確認日の管理 |
| デイからショートへの接続 | サービス間の転換候補管理 |
| ショートからロングへの接続 | 安定利用者・ロング相談候補の管理 |
| 予定表・予約管理 | 利用予定、空き、予約化状況の管理 |
| 相談員タスクリスト | 担当者、対応状況、次アクションの管理 |
| 記録テンプレート | フォロー履歴を後から分析できる形で残す |
| 経営層向けレポート | CRM/SEPに蓄積された現場活動を経営判断につなげる |

| 将来のMicrosoft基盤 | 想定する役割 |
|---|---|
| Power BI | 経営層向け定例レポート、評価観点候補の可視化、部門別・サービス別ダッシュボード |
| Azure | データ保存、処理、自動更新、権限管理、他システム連携の基盤 |
| Windows環境 | 現場・管理職が日常的に使う業務端末上での運用 |

つまり、短期的には病床利用率改善のための現場DXであり、中長期的には老健の顧客接点を管理する基盤づくりである。

## 初回で示したい価値

初回で示すべき価値は、以下である。

1. 病床利用率低下を、単なる稼働率の問題ではなく、利用者の流れとして分解できること
2. データを使って、ショート、ロング、デイ、退所後フォローの関係を追えること
3. 経営層向けには、改善の方向性を分かりやすく示せること
4. 現場DXについては、個人情報を含まない集計と候補テーマとして示せること
5. 一度きりの分析ではなく、継続的な改善サイクルにできること

## 現時点の作業仮説

現時点の分析では、病床利用率低下への初期仮説を以下のように置いている。

- 2026年4-5月のショート + ロング入所率は95.0%
- 98%目標に対して、同期間で180床日不足している
- 前年同期間比では、ロング床日は大きく悪化していない
- 一方で、ショート床日が減少している
- したがって、短期的にはショート床日をどう回復するかが重要である

この仮説は、現場確認と追加データによって修正される前提で扱う。

## 初回の打ち手

初回の打ち手は、病床利用率低下の要因を説明するだけでなく、現場DXとしてどのような改善余地があるかを設計案として示すことである。

具体的には、以下を行う。

1. 利用率低下の構造を整理する
2. ショート、ロング、デイ、退所後の動きを利用者単位で追う
3. 個人情報を含まない範囲で、対象者数・区分別件数・傾向を示す
4. 個人情報を含む候補者リストは、分析担当または管理者限定の内部検証用に留める
5. 配布範囲、運用頻度、責任者、記録方法を次段階の論点として整理する

## 継続的な現場DX改善サイクル

重点フォロー候補は、現場DX施策の候補の一つである。

今後の改善サイクルは、重点フォロー候補を出すことだけを目的にしない。現場で起きている課題を拾い、データや簡易ツールで小さく試し、使えるものを運用に残していくサイクルとして考える。

このとき、各施策は単発の改善で終わらせず、将来の顧客CRM/SEP基盤に必要なデータ、運用、画面、記録項目を少しずつ固める機会として扱う。

```text
1. 現場・管理職・経営層から課題を拾う
2. 課題を「見える化」「リスト化」「記録化」「自動化」「標準化」に分解する
3. 既存データで試せるものを小さく作る
4. 個人情報を含まない集計や設計案として確認する
5. 使える点、負担になる点、判断に効く点を確認する
6. 残す施策、直す施策、やめる施策を決める
7. 経営層向けには、現場DXの進捗と経営課題への影響を報告する
```

このサイクルによって、経営層向けレポートと現場DXを分離せず、同じ改善活動としてつなげる。

病床利用率低下への対応では、重点フォロー、退所後フォロー、デイからショートへの接続、3F候補、予定表確認、記録テンプレートなどが初期の現場DX候補になる。どれから着手するか、どこまで現場配布するか、どの頻度で運用するかは、個人情報取扱と運用ルールを確認したうえで決める。

## 今後広げる現場DXテーマ

初回は病床利用率低下を扱うが、老健全体の改善テーマはそれだけではない。

今後は、以下のような現場DXテーマへ広げる。

| テーマ | 狙い | 初期の扱い |
|---|---|---|
| 重点フォロー候補 | 病床利用率改善のため、将来的に見るべき利用者層を絞る | 個人情報なしの件数・区分別集計、内部検証用リスト |
| 退所後フォロー | 退所者を放置せず、再利用・通所・ショートにつなげる余地を見る | 退所後30日・60日・90日確認の設計案 |
| デイからショートへの接続 | デイ利用者を初回ショート候補として見られるか検討する | 高頻度デイ利用者の件数・傾向集計 |
| ショートからロングへの接続 | 安定利用者をロング相談につなげる余地を見る | ショート15日以上・ロング未転換の件数・傾向集計 |
| 3F受け入れ候補 | 3Fの空床対策として、適合条件を検討する | 3F利用歴・状態確認の設計案 |
| 予定表・予約管理 | 未来予約、空き、重複、確認漏れを見える化する | 予定表確認ロジックの設計案 |
| 相談員業務 | 対応状況、次回確認日、担当者を整理する | タスク管理項目の設計案 |
| 現場記録の標準化 | 記録のばらつきを減らし、次の判断に使える形にする | 選択式記録テンプレート案 |
| 経営層向け定例レポート | 現場DXの検討・実行状況を経営判断につなげる | 月次・週次サマリー案 |

重要なのは、最初から大きなシステムを作ることではない。

現場で困っていることを、リスト、チェック、記録、集計、通知、レポートといった小さなDXに分け、使えるものから順に残していく。

その積み上げによって、後からCRM/SEPとして統合したときに、現場にとって使えるシステムになるようにする。
