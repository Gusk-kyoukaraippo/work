# MVP3：JSON内蔵型セーブ管理

## 概要

- `MVP3rd/` をMVP1と独立して作成し、互換処理・移行マクロは設けない。
- `.xlsm` の組み立てはMac版Excelで行い、完成後は `MVP3rd` フォルダ一式をWindows環境へコピーして運用する。
- `.xlsm` をHTML起動とセーブ管理の入口にし、利用者に見せるシートは保護された `操作パネル` 1枚だけとする。
- 最新版JSONは `.xlsm` 内へ分割保存し、アップロード原本と全履歴は `html/json` に残す。
- HTMLから作成したJSONは利用者PCへダウンロードし、VBAが現在のExcel起動中・現在の編集作業に対応するものだけをローカルのダウンロードフォルダから自動検出する。
- JSONのpayloadはExcel表へ変換せず保持するため、異なるJSON構造、配列、入れ子、型、未知項目に共通VBAで対応する。
- 過去版復元、状態確認、管理者モード、MVP1互換は対象外とする。

## JSON・内部データ

出力JSONの共通外枠を次に統一する。

```json
{
  "formatVersion": 2,
  "saveDataId": "一意ID",
  "parentSaveDataId": null,
  "sessionId": "編集セッションID",
  "databaseId": "ブック固有ID",
  "dataType": "HTMLデータ種別",
  "schemaVersion": 1,
  "baseRevision": 125,
  "exportSequence": 1,
  "authorName": "山田 太郎",
  "exportedAt": "2026-07-15T01:00:00.000Z",
  "saveKind": "complete",
  "readOnly": false,
  "payload": {}
}
```

`saveKind` は内部判定用とし、利用者向け画面にはこの名称を表示しない。

- `workCopy`：作業中のデータをPCへ保存し、そのまま同じHTMLで編集を続ける。Excelへの取り込みは任意とする。
- `complete`：作業を終えてExcelへ保存する。取り込み成功後に編集作業を終了扱いにする。

`exportSequence` は同じ編集作業内で1から増やす。`parentSaveDataId` は同じHTMLが直前に作ったJSONのsaveDataIdとし、最初のJSONだけnullにする。

HTMLはsessionIdをキーとしてexportSequenceと直前のsaveDataIdだけをブラウザの `sessionStorage` に保持し、再読み込み後も番号と保存のつながりが戻らないようにする。利用者名と業務データはブラウザへ保存しない。VBAは、現在の編集作業で最後に取り込んだ番号より大きいデータだけを受け付け、同じデータの二重取り込みを防ぐ。

中央モーダルの `もう一度ダウンロードする` は新しいJSONを作らず、直前にメモリ上で生成したJSONを同じsaveDataId、exportSequence、内容のまま再ダウンロードする。編集画面へ戻って再び保存操作を行った場合だけ、次のexportSequenceを発行する。

内部シートはすべて `xlSheetVeryHidden` にする。

- `_APP_DATA`：最新版JSONを20,000文字ずつ分割し、分割番号と本文を保存
- `_APP_META`：databaseId、dataType、schemaVersion、revision、chunkCount、jsonLength、CRC32、編集中のsessionId、編集開始時revision、最後に取り込んだexportSequence、最後に取り込んだsaveDataId、commitState
- `_APP_HISTORY`：成功した保存のrevision、取込完了日時、保存者、外部ファイル

保存前にJSON文字列内部には触れず、文字列外の空白・改行・インデントだけを除去する。Excelの1セル上限32,767文字に対して余裕を持たせ、サロゲートペア途中では分割しない。[Microsoft Support](https://support.microsoft.com/es-ES/Excel/excel-specifications-and-limits)

読み出し時は番号順に連結し、分割数・文字数・CRC32が一致した場合だけHTMLへ渡す。入力上限はUTF-8で10MiB、展開後10,485,760文字、JSON深度64とする。

```text
html/json/
├─ accepted/YYYY-MM/
├─ rejected/YYYY-MM/
├─ .pending/
└─ .sessions/
```

- acceptedにはアップロード原本を無加工で保存する。
- `.xlsm` 内には意味的に同一の空白除去版を保存する。
- rejectedには、現在のdatabaseId・sessionIdに対応する保存用JSONだと確認できた後、詳細検証で拒否した原本と理由だけを保存する。無関係なJSONや別のExcel用JSONは共有サーバーへコピーしない。revisionや最新版表示は変更しない。
- `workCopy` も通常の取り込み対象にできるが、ダウンロードのたびに取り込む必要はない。利用者が取り込んだ場合だけrevisionと正式履歴を更新し、JSON原本をacceptedへ保存する。利用者PCにダウンロードされた元ファイルは削除しない。
- 内部JSONが破損した場合はHTMLを開かず、acceptedからの開発者復旧を案内する。

## 利用者名

- `編集する` でHTMLを開いた直後に、毎回空欄から利用者名を入力させる。
- 共有PCのためWindowsユーザー名やブラウザ保存情報は使用しない。
- 前後空白除去後の1～50文字を必須とし、制御文字を拒否する。
- 名前を確定するまで編集画面へ進めない。
- 通常ヘッダーには名前を常時表示しない。
- `閲覧する` では名前を入力させない。

セーブデータ出力時に次を確認する。

```text
保存者：山田 太郎さん
この名前でセーブデータを作成します。
```

利用者は「この名前で出力」「名前を修正」「キャンセル」を選べる。

編集後は次のように名前付きで案内する。

```text
山田 太郎さん、作業した内容は
まだExcelに保存されていません。
```

作業を終えてExcelへ渡すデータを作った後は、次を表示する。

```text
山田 太郎さん、Excelへ渡すデータの
ダウンロードを開始しました。

Excelへ戻り、
「セーブデータをExcelに保存する」を押してください。
この操作が終わると、Excelへの保存が完了します。
```

VBAは `authorName` を再検証し、成功後に履歴、最新版カード、ファイル名へ反映する。ファイル名ではWindows使用禁止文字だけを除去し、JSON本文には正式な入力値を残す。

## HTMLでの保存操作

利用者向け画面では「未完了」「途中保存」「最終保存」という用語を使わず、操作内容をそのままボタン名と説明文にする。

HTMLの保存操作では次の2つを選べるようにする。

- `作業中のデータをPCに保存して、編集を続ける`
- `作業を終えて、Excelへ渡すデータを作る`

作業中のデータを保存する場合は `saveKind=workCopy` としてダウンロードを開始する。利用者はExcelへ戻らず、そのままHTMLで編集を続けてよい。このJSONは必要に応じてExcelの `セーブデータをExcelに保存する` から通常どおり取り込むこともでき、その場合はrevision、最新版カード、履歴、accepted原本を更新する。取り込んでも編集作業そのものは終了扱いにしない。

`saveKind=complete` の保存が開始されたら、HTMLの編集画面とヘッダーを非表示にし、Excelへ戻る案内、作成したファイル名、再ダウンロード操作だけを持つ最小画面へ切り替える。ブラウザタブ自体は強制終了しない。

保存履歴HTMLには `閲覧を終了` を設ける。利用者の操作で `window.close()` を試し、ブラウザの制限で閉じられない場合は履歴一覧を消してExcelへ戻る案内だけを表示する。

`_APP_META` の値はセルの表示形式を文字列へ設定してから保存し、日時文字列のExcel日付シリアル値への自動変換を防ぐ。既存データの `lastSaveAt` と `sessionStartedAt` が数値化されている場合は、読み出し時にDateへ戻して標準の日時文字列へ補正する。終了確認へは未整形値を直接連結しない。

```text
作業中のデータについて、PCへの保存を開始しました

ファイル名：MVP3SAVE_～.json
ブラウザのダウンロード表示に、このファイルがあることを
確認してください。

このまま編集を続けられます。

この時点の内容をExcelにも残したい場合だけ、Excelへ戻り
「セーブデータをExcelに保存する」を押してください。

このデータを次回の作業にも残すには、Excelを閉じる前に
「セーブデータをExcelに保存する」を押してください。
```

この中央モーダルには、実際に生成したファイル名、ブラウザのダウンロード表示を確認する案内、主ボタン `このまま編集を続ける`、補助ボタン `もう一度ダウンロードする` を配置する。Excelへの取り込みを要求するモーダルにはしない。

作業を終える場合は `saveKind=complete` としてダウンロードを開始する。開始後はHTMLを編集終了状態にし、編集画面へは戻せない。このデータだけはExcelへの取り込みを必須とし、取り込み成功まで操作パネルの赤表示と作業中の記録を維持する。中央モーダルには出力ファイル名、ブラウザのダウンロード表示を確認する案内、Excelで行う次の操作を大きく表示し、ファイルが見つからない場合に備えて `もう一度ダウンロードする` だけを用意する。

中央モーダルはVBAではなく、HTML内のHTML・CSS・JavaScriptで実装する。ブラウザはファイルの保存完了を確実に通知しないため、「ダウンロードが完了しました」ではなく「ダウンロードを開始しました」と表示する。[MDN](https://developer.mozilla.org/en-US/docs/Web/API/HTMLAnchorElement/download)

HTMLからExcelへ自動的に画面を切り替える処理は、ブラウザやPC環境によって動作が安定しないため設けない。

## ダウンロードフォルダからの取り込み

HTMLは保存先フォルダを強制できないため、標準のダウンロード機能で識別しやすいファイル名を指定する。

```text
MVP3SAVE_<databaseId先頭8文字>_r<編集開始時revision>_s<exportSequence>_<保存区分>_<日時>_<保存者>_<saveDataId先頭8文字>.json
```

ブラウザが同名ファイルへ `(1)` などを付加する場合があるため、ファイル名だけを信用せずJSON本文を検証する。

`ImportSaveData` は次の順序で対象を探す。

1. WindowsのKnown Folderから、現在の利用者のダウンロードフォルダを取得する。
2. 取得できない場合は `%USERPROFILE%\Downloads` を使用する。
3. ダウンロードフォルダ直下だけを検索し、専用ファイル名で始まる `.json` のうち、現在のdatabaseId・sessionIdと一致し、まだ取り込まれていない `workCopy` または `complete` を検証する。
4. 有効なファイルが複数ある場合は、最も大きいexportSequenceを選び、保存者、出力日時、保存区分、ファイル名を表示して取り込み確認を出す。
5. 対象がない場合、または利用者が自動検出したファイルを選ばなかった場合は、ダウンロードフォルダを最初に表示したファイル選択画面を開く。

ファイル選択は `Application.FileDialog` の `InitialFileName` を優先する。JUST Calcで利用できない場合は、一時的にカレントフォルダをダウンロードフォルダへ変更して `GetOpenFilename` を実行し、終了後に元のフォルダへ必ず戻す。[Microsoft Learn: FileDialog.InitialFileName](https://learn.microsoft.com/en-us/office/vba/api/office.filedialog.initialfilename) / [Microsoft Learn: GetOpenFilename](https://learn.microsoft.com/en-us/office/vba/api/excel.application.getopenfilename)

`.crdownload` や `.part` は対象外とする。現在の編集作業に対応するJSONが見つからない場合は、専門用語を使わず次を表示する。

```text
この作業で作った保存用データが見つかりません。

HTMLへ戻り、
保存操作を行ってください。
```

すでに取り込んだsaveDataIdまたはexportSequenceが選ばれた場合は、revisionを増やさず「このデータはすでにExcelへ保存されています」と表示する。複数回出力してから取り込んだ場合は、最も大きいexportSequenceだけを最新版として取り込む。

現在のsessionIdに対応する候補は、parentSaveDataIdから保存のつながりを組み立てる。同じparentSaveDataIdから異なるsaveDataIdが複数作られている場合は、ブラウザタブの複製などで編集内容が二股に分かれたものと判定し、exportSequenceの大小にかかわらず自動選択も手動選択も許可しない。同じsaveDataId・同じ内容の再ダウンロードは同一データとして扱う。

```text
編集画面が複数に分かれています。
どちらが正しい内容かExcelでは判断できません。

開いているHTMLとExcelをすべて閉じて、
Excelを開き直してから編集してください。
```

取り込み成功後も、利用者PCにダウンロードされた元のJSONは削除しない。

### 誤った手順を正しいと覚えさせないための原則

利用者が偶然成功した操作を正しい手順だと覚えないよう、保存結果と案内を常に一致させる。

- Excelを閉じた後も残るのは、`セーブデータをExcelに保存する` が成功した内容だけとする。
- PCへダウンロードしただけのJSONを、次回起動時に自動検出・自動回復しない。
- 前回のsessionIdを持つJSONや、前回のExcelから開いたまま残っているHTMLが作ったJSONは、新しいExcel起動後には受け付けない。
- 作業中データの取り込みを、作業終了データの取り込みへ自動的に読み替えない。
- 同じデータの再ダウンロード、ボタンの二度押し、同じJSONの再選択ではrevisionを増やさない。
- 検証失敗、ネットワーク失敗、ブック保存失敗では、最新版カード、保存時刻、保存者を成功したように更新しない。
- ファイル名が正しそうに見えてもJSON本文が現在のdatabaseId・sessionId・exportSequenceと一致しなければ受け付けない。

取り込み成功時の文言は保存区分によって変える。

```text
作業中のデータの場合：
この時点の内容をExcelに保存しました。
HTMLで始めた作業は、まだ終了していません。

作業終了データの場合：
今回の作業内容をExcelに保存しました。
保存は完了しています。
```

## 操作パネルとマクロ

操作パネルには次の5ボタンだけを配置する。

- `閲覧する`
- `編集する`
- `セーブデータをExcelに保存する`
- `これまでの保存を見る`
- `終了する`

対応する利用者向けマクロは次の5個とする。

```vb
OpenReadOnlyHtml
OpenEditHtml
ImportSaveData
OpenSaveHistory
ExitWorkbook
```

導入用に `InitializeMvp2`、タイマー用に `Mvp2TimerTick` を別途用意する。

VBAはメイン制御、JSON検証・分割保存、操作パネル・タイマー、ファイル履歴のモジュールへ分ける。`ThisWorkbook` には `Workbook_Open`、`Workbook_Activate`、`Workbook_BeforeClose` を配置する。

### 読み取り専用で開いた場合

共有サーバー上のブックをほかの利用者が編集中の場合など、`ThisWorkbook.ReadOnly=True` で開かれたブックは閲覧専用モードとする。

- 操作パネル上部に `このExcelは読み取り専用で開いています。閲覧のみ利用できます。` と表示する。
- 赤・黄・緑の保存状態は閲覧できるように残すが、状態文中の「編集する」「保存ボタンを押す」など実行できない案内は、読み取り専用では `このExcelでは閲覧だけできます。` に置き換える。
- 操作パネル下部の通常手順も、読み取り専用では `データの入力・編集・保存はできません。「閲覧する」または「これまでの保存を見る」を利用してください。` に置き換える。
- 5ボタンの数と名称は変えない。
- `編集する` と `セーブデータをExcelに保存する` はグレー表示にし、ボタンへのマクロ割り当てを一時的に外して押しても動かない状態にする。
- `閲覧する`、`これまでの保存を見る`、`終了する` は利用できる。
- 読み書き可能な状態で開き直した場合は、画面更新時に編集・保存ボタンの色とマクロ割り当てを元へ戻す。
- マクロ一覧などから `OpenEditHtml` または `ImportSaveData` が直接実行された場合にも、既存の読み取り専用チェックで処理を拒否する。画面上の無効化だけを安全判定には使わない。
- 読み取り専用の閲覧者は、作業中記録や `commitState=PREPARED` が見えていても変更・確定・解除しない。
- 読み取り専用の終了時は、作業中記録を変更せず、`読み取り専用で開いています。Excelを終了しますか？` と確認して閉じられるようにする。他の利用者の作業中記録を理由に終了を妨げない。

図形ボタンに実行可否を表す共通プロパティがない環境もあるため、VBAでは図形名を固定し、色と `OnAction` の両方を切り替える。JUST Calcで `OnAction` の変更が利用できない場合でも、公開マクロ側の読み取り専用チェックを必ず残す。

### HTMLを開く前の軽量確認

共有サーバーの確認によってExcel自体の起動が遅くならないよう、`Workbook_Open` では読み取り専用状態の確認だけを行う。共有フォルダへのアクセス確認は、利用者が `編集する` を押した直後に1回だけ実行する。

`OpenEditHtml` は作業中の記録を作る前に、次を順番に確認する。

1. ブックが読み取り専用ではなく、保存先となる `ThisWorkbook.Path` が確定している。
2. ブックからの相対パスにHTMLテンプレートが存在する。
3. `html/json/.pending` が存在する。
4. `.pending` に一意な名前の小さな確認用ファイルを作成し、閉じた後に削除できる。

確認に失敗した場合は、作業中の記録を作らずHTMLも開かない。利用者には「共有フォルダへ接続できません」「このExcelは読み取り専用です」など、失敗した操作に対応する短い案内を表示する。

正常な社内LANでは確認全体を0.1～0.5秒程度、VPNや遅い共有サーバーでは0.5～3秒程度の想定とする。ネットワーク切断時はWindows側の待ち時間が発生する可能性があるため、確認対象を上記の1フォルダと1ファイルに限定する。

この確認では、accepted・rejected・履歴の全件走査、内部JSON全体の再検証、`.xlsm` の試験保存を行わない。内部JSONの整合性確認はHTML生成時の通常処理、実際の書き込み可否の再確認は `ImportSaveData` の開始時と確定処理内で行う。

### 保存状態

操作パネル上部に状態帯と、最新版・1つ前の保存情報を表示する。

読み取り専用の場合は、赤・黄・緑の保存状態とは別の案内帯をタイトル直下に表示する。保存状態そのものは変更せず、閲覧者が最新版と作業状況を確認できるようにする。

1. HTMLで始めた作業がExcel側で終了していない：赤
2. PC時刻が、最後にExcelへ保存した時刻より前：黄
3. 最後にExcelへ保存してから24時間以上：黄
4. 保存履歴なし：黄
5. それ以外：緑

赤色の状態では「未完了」「未取り込み」という言葉を使わず、次のように表示する。

```text
HTMLで始めた作業が、Excel側でまだ終了していません

HTMLで作業を始めた時刻：10:05
最後にExcelへ保存した時刻：09:42
現在時刻　　　　　　　　：10:33
経過時間　　　　　　　　：28分

作業中の内容をExcelにも残したい場合は、HTMLで保存用データを作り、
この画面の「セーブデータをExcelに保存する」を押してください。

作業が終わったときは、HTMLで
「作業を終えて、Excelへ渡すデータを作る」を選んでください。

PCへ保存しただけのデータは、Excelを閉じた後の作業には
引き継がれません。
```

最新版と1つ前には、revision、取込完了日時、保存者を表示する。拒否されたJSONでは更新しない。

`Application.OnTime` で1分ごとに更新し、二重予約を防止して終了前に解除する。JUST Calcで利用できない場合は、起動・再アクティブ化・ボタン操作・終了時更新へ自動的に切り替える。[Microsoft Learn](https://learn.microsoft.com/en-us/office/vba/api/excel.application.ontime)

タイマーによる画面更新だけではブックを未保存状態にしない。

### 編集と取り込み

- `Workbook_Open` ごとに一意なworkbookRunIdをメモリ上で発行する。`OpenEditHtml` はsessionId、workbookRunId、開始時刻を `.sessions` に作業中の記録として保存してからHTMLを開く。
- HTMLで始めた作業がExcel側で終了していない場合は、新しい編集画面を重ねて開かない。
- HTMLを閉じた後に `編集する` を押した場合は、新しいHTMLを開かない。現在のExcelをまだ閉じていなければ、先に `セーブデータをExcelに保存する` から最新のデータをExcelへ保存できることを案内する。
- `ImportSaveData` は共有サーバーへコピーする前に、選択したPC上のファイルを読み取り専用で事前確認する。拡張子、ファイルサイズ、UTF-8、JSON構文、formatVersion、databaseId、dataType、sessionIdを確認し、現在のExcel用データと確認できた場合だけpendingへコピーする。
- 無関係なJSON、別のExcel用JSON、前回起動時のJSONはpendingやrejectedへコピーせず、利用者へ理由だけを表示する。pendingへコピーした後にschemaVersion、baseRevision、exportSequence、parentSaveDataId、保存の分岐、authorName、payloadを詳細検証する。
- 同じsessionIdでは、baseRevisionが編集開始時revisionと一致し、exportSequenceが最後に取り込んだ番号より大きい場合だけ受け付ける。同じ編集作業中にworkCopyを取り込んで現在revisionが増えていても、同じsessionIdからの続きとして扱う。
- `saveKind=workCopy` の成功時は、内部JSON、revision、履歴、accepted原本、最新版カードを更新して `.xlsm` を保存する。作業中の記録は残し、最後に取り込んだexportSequenceを更新する。
- `saveKind=complete` の成功時も同じ保存処理を行い、すべての確定処理が終わった後にだけ作業中の記録を解除する。
- PC上の事前確認を通過した現在のExcel用JSONについて、詳細検証で内容が不正だった場合だけ原本と理由をrejectedへ保存する。ネットワーク切断やExcel保存失敗などの環境エラーではrejectedへ移さず、pendingに残して再処理できるようにする。

### 取り込みの確定手順

Excelファイルと外部JSONを完全に同時確定することはできないため、`commitState` を使った二段階処理にする。

1. 選択したPC上のファイルを読み取り専用で事前確認し、現在のdatabaseId・dataType・sessionIdに対応する保存用JSONかを判定する。この段階では共有サーバーへコピーしない。
2. 対象と確認できたJSONだけを `.pending/<saveDataId>.json` へコピーし、元ファイルとのバイト一致を確認する。
3. schemaVersion、baseRevision、exportSequence、parentSaveDataId、保存の分岐、authorName、payloadを詳細検証する。
4. acceptedの保存月と正式ファイル名を決める。対象の `accepted/YYYY-MM/` で小さな一時ファイルを作成・削除し、書き込み可能であることを確認する。
5. Excelへ保存する内部JSONと履歴情報を準備する。
6. `_APP_META` を `commitState=PREPARED` にし、内部JSON、revision、仮の履歴行を更新して `.xlsm` を保存する。
7. pending原本をaccepted側の一時ファイルへコピーし、バイト一致を確認してから正式名称へ変更する。検証が終わるまで正式なacceptedファイルとして扱わない。
8. 正式名称のファイルがすでに存在する場合は、pending原本とバイト単位で一致すればコピー済みとして続行する。一致しない場合は上書きせず、PREPAREDとpendingを残して処理を停止する。
9. 履歴行を確定状態へ変更する。`complete` の場合だけ作業中の記録を解除し、`commitState=NONE` として `.xlsm` をもう一度保存する。
10. 2回目のブック保存まで成功した場合だけ、操作パネルとダイアログに「Excelへの保存が完了しました」と表示する。

手順6より前に失敗した場合は、Excel内部の変更を元へ戻して作業中表示を維持する。手順6以降に中断した場合はPREPARED、pending原本、accepted側の一時ファイルを残し、次回の `Workbook_Open` で手順7以降を同じ結果になるよう自動再実行する。再実行が成功するまで編集・追加取り込みは許可しない。

### 履歴と終了

- `これまでの保存を見る` は、成功した保存だけを読み取り専用HTMLで表示する。復元・編集機能は置かない。
- `終了する` とウィンドウの×は同じ判定を使用する。
- HTMLで始めた作業がExcel側で終了していない場合は、次の警告を表示し、既定ではExcelへ戻す。

```text
Excelに保存されていない作業がある可能性があります。
このまま終了すると、次回には引き継がれません。

保存せずに終了しますか？
```

終了ダイアログには説明を詰め込まず、詳しい保存手順と「PCへ保存しただけでは次回に引き継がれない」という案内は、操作パネルの赤表示とHTMLの中央モーダルに常時表示する。既定値は「いいえ」とし、Excelへ戻す。

- 利用者が保存せずに終了することを明示的に選んだ場合は、作業中の記録を解除してブックを閉じる。次回は最後にExcelへの保存が成功した内容から編集を始める。
- 保存せず終了しても、過去の正式データとaccepted履歴は削除しない。
- 保存済みなら最新版の保存日時と保存者を表示して終了確認する。
- 読み取り専用で開いた場合は、保存状態や作業中記録を変更せず、読み取り専用であることだけを表示して終了確認する。作業中記録の解除やPREPAREDの確定は行わない。

ExcelはHTMLが現在開いているか、通常終了したかを確実には判定できないため、Excelを開いたまま `編集する` が再度押された場合は「異常終了」と断定しない。

```text
HTMLで始めた作業が、Excel側に残っています。

編集画面が開いている場合は、その画面へ戻ってください。
編集画面を閉じてしまった場合でも、PCへ保存したデータがあれば
「セーブデータをExcelに保存する」からExcelへ保存できます。

必要なデータを取り込んだ後、Excelを終了して
もう一度開いてください。

最後にExcelへ保存した内容から始められます。
```

ExcelまたはPCが異常終了し、作業中の記録が残ったままブックが再度開かれた場合は、読み書き可能な状態であることを確認してから次を表示する。

```text
前回、HTMLでの作業を終えないままExcelが閉じられました。

最後にExcelへ保存できた内容から始めます。
PCへ保存しただけのデータは引き継がれません。
```

前回の作業中記録にあるworkbookRunIdが今回の起動と異なる場合は、前回のExcelが終了したものと判定する。`commitState=PREPARED` の場合だけ、利用者がすでにExcelへの保存を開始していた処理としてaccepted保存と履歴確定を自動再実行する。これは保存済み処理の整合性回復であり、ダウンロードフォルダから利用者データを探す処理ではない。

PREPAREDがない場合、またはその確定が終わった後は、前回の作業中記録を解除する。ダウンロードフォルダを検索せず、前回のsessionIdを持つJSONを通常画面から取り込めないようにする。新しい編集は、最後にExcelへの保存が成功した内容から開始する。

前回のsessionIdを持つJSONが手動で選択された場合は、rejectedへ移して通常のJSONエラーとだけ表示するのではなく、次を表示する。revision、履歴、最新版カードは更新しない。

```text
前回のExcelで開いた編集画面のデータです。
現在のExcelには保存できません。

現在のExcelの「編集する」から、編集画面を開き直してください。
```

ブックが読み取り専用の場合は、PREPAREDの確定、作業中記録の解除、編集、取り込みを行わず、読み取り専用であることを案内する。

HTMLでは「最後にJSONのダウンロードを開始した後、新しく変更された内容があるか」を `dirtySinceDownload` として管理する。利用者が実際に編集したときだけtrueにし、workCopyまたはcompleteのJSON生成とダウンロード開始処理が成功した時点でfalseに戻す。ブラウザの `beforeunload` はdirtySinceDownloadがtrueの場合だけ有効にし、同じ意味の警告を繰り返して無視する習慣が付かないようにする。

workCopyのダウンロード後にHTMLを閉じても、Excel側では作業中の記録と赤表示を維持する。PCに保存したJSONをExcelへ残すかどうかは、Excelの終了警告で改めて案内する。completeの場合はHTMLを編集終了状態にする。ブラウザ標準の終了確認文は変更できないため、名前付き案内はHTML画面内で行う。[HTML Standard](https://html.spec.whatwg.org/multipage/browsing-the-web.html)

## 保護とテスト

- 利用者から見えるシートは操作パネル1枚だけとし、セル入力、貼り付け、削除、書式変更、行列操作を禁止する。
- 内部シートはVeryHidden、ブック構造はパスワード付き保護とする。
- マクロは必要な範囲だけ保護解除し、成功・失敗を問わず再保護する。

- JSONの空白除去結果と、保存・終了・再起動後の連結結果が一致する。

- HTMLの2種類の保存操作、中央モーダル、編集継続、編集終了後のロック、再ダウンロードが正しい。

## 成果物

### VBAソースの文字コード

VBAエディターはUTF-8の `.bas` を直接インポートすると日本語文字列が文字化けする場合がある。このため、Mac版Excelでの `.xlsm` 組み立て用と保守用に、次の2系統を同じ内容で保持する。MicrosoftもWindowsで書き出した `.bas` をMac版Excelへインポートする手順を案内している。[Microsoft Support](https://support.microsoft.com/en-US/Excel/import-and-shape-data-in-excel-for-mac-power-query)

- `vba/*.bas`：Mac版Excelへ直接インポートして `.xlsm` に組み込むCP932（Windows-31J）版
- `vba/utf8/*.bas`：コードレビュー、差分管理、修正に使うUTF-8版

導入手順ではMac上で `vba/*.bas` をインポート対象として案内する。UTF-8版を修正した場合は、配布前にCP932へ変換し、日本語文字列とモジュール名が一致することを自動テストする。`ThisWorkbook.txt` はイベント呼び出しだけで日本語文字列を持たないため、UTF-8のまま貼り付け用として配布する。

Macで作成した `.xlsm` にはVBAプロジェクトが内蔵されるため、Windows側で `.bas` を再インポートしない。Windowsへは `.xlsm` 単体ではなく、相対パスで参照する `html` と `html/json` を含む `MVP3rd` フォルダ一式をコピーする。実運用の編集・JSON取り込みはWindowsで行い、Windows固有の `ADODB.Stream`、`WScript.Shell`、`Shell.Application` はWindows実機で確認する。
