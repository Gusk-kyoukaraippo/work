# MVP3.5 院内難病患者・包括管理台帳

更新日：2026年7月19日

## 目的

MVP3.5の主目的は、外来診察、外来リハ、不定期入院、定期入院で分断されている難病患者情報を、患者単位で一元把握できる院内台帳を作ることである。

MVP3の病床管理を残しつつ、システムの中心を「病床」から「患者と当院との継続的な関係」へ広げる。

本台帳は、詳細な診療録や介護記録を複製するものではない。「どのサービスを利用しているか」「誰が担当しているか」「現在どのような調整状態か」を短時間で俯瞰し、院内の患者把握と部門間調整に使う。

声掛け、利用途絶の発見、空床と当日外来患者の照合は、台帳から得られる付随効果と位置付ける。

## 将来像

一人の患者へ、院内外の医療・介護サービスとの関係を同じ構造で紐づける。

- 外来診察
- 外来リハ
- 入院
- デイサービス
- ショートステイ
- 訪問看護
- 訪問リハ
- 居宅介護等の地域サービス
- 院外の連携事業所

将来サービスを追加するときは、サービス台帳へ種類を追加する。患者データの構造変更や作り直しは行わない。

デイサービス等について保持するのは、事業所、利用状態、頻度、担当部署、最終確認日などの関係情報までとする。日々の詳細記録、ケア計画、診療録は保持しない。

## MVP3.5で実現すること

### 1. 第3タブ「難病患者台帳」

MVP3rdを残したまま、MVP3.5へ次の3画面を設ける。

1. 病床ボード・手動調整
2. 次回日程・部屋調整
3. 難病患者台帳

難病患者台帳は1患者1行とし、次を横断表示する。

- 患者氏名、CP、CP確認状態
- 疾患区分、元病名、確認状態
- 外来診察の最終実績、判明している次回予定
- 外来リハの最終実績、判明している次回予定
- 最終入院、今後の入院予定
- 定期入院、不定期入院、未確認
- 障害者病棟の病状的適応
- 担当部署、必要最小限の調整状態

### 2. 利用形態を組み合わせた検索

次の4つを任意に選び、「すべて含む」または「いずれかを含む」で検索できるようにする。

- 外来診察
- 外来リハ
- 不定期入院
- 定期入院

このほか、疾患区分、疾患登録状態、入院区分、障害者病棟適応、台帳状態で絞り込めるようにする。

### 3. 患者詳細と統合時系列

患者詳細では、次を一画面で確認・更新する。

- 疾患と元病名
- 入院区分と定期入院の目安
- 障害者病棟の病状的適応
- 担当部署と調整状態
- サービス利用関係
- 外来・外来リハの実績と判明している予約
- 部門間確認、声掛け、入院調整等の最小限の履歴
- 外来、リハ、入退院、主要調整記録をまとめた直近24か月の時系列

### 4. 入院履歴からの判断材料

入院履歴から利用回数と入院間隔の中央値を提示する。

- 入院1回のみの場合は、不定期入院候補として表示する。
- 複数回利用の場合は、回数と間隔を判断材料として表示する。
- システムは定期・不定期を自動確定しない。
- 最終区分は履歴を確認した職員が確定する。
- 退院実績日時を取得できない既存記録は、退院予定日を「予定値」と明示して表示する。

### 5. 入院調整への引き継ぎ

台帳の患者一覧または患者詳細から、既存の「次回日程・部屋調整」へ直接進める。

患者と確認済みの性別だけを引き継ぎ、希望日程や部屋を自動決定しない。既存の候補検索、再確認、配置待ち登録の流れをそのまま利用する。

## 対象患者と疾患区分

台帳対象は、医療費助成の申請・認定状況にかかわらず、当院で次の疾患を診断・診療している患者とする。

1. パーキンソン病
2. 多系統萎縮症
3. 進行性核上性麻痺
4. 脊髄小脳変性症
5. 筋萎縮性側索硬化症（ALS）
6. CJD
7. その他（神経）
8. その他（神経以外）

運用原則は次のとおりとする。

- 一人へ複数疾患を登録できる。
- 「その他」では院内区分だけでなく、元の病名を必ず保持する。
- 病名情報から候補を作ることはできるが、台帳への確定登録は職員が行う。
- 疑い病名、終了病名、確定状態を取得できない病名は自動確定しない。
- 同名患者を氏名だけで統合しない。

## schema v5のデータ設計

既存の `patients`、`admissions`、`assignments` を維持し、次を追加する。

| コレクション | 役割 |
|---|---|
| `patientDiseases` | 患者、院内疾患区分、元病名、確認済み・確認待ち・終了 |
| `serviceCatalog` | 外来診察、外来リハ、入院、将来の介護・地域サービスの種類 |
| `patientServiceRelations` | 利用中・休止・終了、事業所、頻度、担当部署、最終確認日 |
| `serviceEvents` | 取得可能な外来・外来リハの実績と予約 |
| `admissionProfiles` | 定期・不定期・未確認、目安間隔、病棟適応、調整状態、確認履歴 |
| `coordinationRecords` | 部署間確認、声掛け、入院調整、地域連携等の最小限の履歴 |

## データの正本と運用原則

- 外来・リハ等の各部門システムは、実績と予約の正本として残す。
- MVP3.5は、疾患区分、サービス利用関係、入院パターン、横断調整情報の正本とする。
- 正式CPを患者照合キーとする。
- 現在の仮CPは職員が正式CPを確認した後に統合する。
- 統合時は入院、疾患、サービス関係、イベント、入院プロファイル、調整記録の患者参照を一括で付け替える。
- 統合元患者は削除せず、年度別アーカイブに残す。
- CSVの列、ファイル構成、予約出力方法は現時点で固定しない。
- 実サンプルを確認して取込口を合わせ、取得できない項目は「不明」として扱う。
- 予約情報を取得できない場合は「予約なし」ではなく「予約情報未連携」と表示する。
- 予約連携済みで将来予約が0件の場合に限り「次回予約なし」と表示する。
- 院内の一つのJSONを排他運用し、中央管理部署が正本を管理する。
- ブラウザ内の一時保存は復旧用であり、正本JSONの代替にしない。

## 台帳から発展させる機能

### 定期入院の目安超過

定期入院として職員が確定し、目安日数を過ぎ、今後の入院予定がない患者を抽出する。

### 外来・リハ利用者の把握

外来または外来リハを利用しており、入院利用がない患者を抽出する。

### 長期利用途絶

外来、外来リハ、入院の最終利用から長期間経過した患者を抽出する。調整記録だけでは利用実績とみなさない。

### 空床候補確認

数日間の空床が発生した際、指定期間について次の条件を照合する。

- 本日の外来実績が取得されている
- 疾患区分が職員確認済みである
- 障害者病棟の病状的適応が「適応」である
- 指定期間に既存入院予定が重ならない

候補には自動スコアや自動優先順位を付けない。氏名順で、疾患、最終入院、既存予定、病棟適応等の判断材料だけを表示する。実際の入院可否や声掛けは、その都度主治医・病棟が判断する。

## アーカイブ

- 診療終了・休止の患者は通常一覧から外す。
- 職員確認後に年度別アーカイブへ移す。
- 既定の保管目安は5年とし、運用確定後に設定値を変更できる構造にする。
- アーカイブは削除ではなく、参照可能な状態変更として扱う。

## 検証と成功条件

- 4つの利用形態を任意に組み合わせた患者を、重複なく1人の患者として表示できる。
- 患者を開けば、当院との関わり方と直近の利用状況を短時間で把握できる。
- 疾患区分、利用形態、入院区分、病棟適応で対象患者を絞り込める。
- 複数疾患、疑い病名、終了病名、同名患者、仮CP統合を安全に処理できる。
- 入院パターンを自動確定せず、履歴を見た職員が定期・不定期を確定できる。
- 病床ボード、転床、配置待ち、次回日程検索などMVP3の機能を壊さない。
- 数百〜数千人、直近24か月の利用履歴を単一HTMLで扱える。
- 一覧は患者単位の索引を作成してから50人単位で表示し、患者数と履歴数の積に比例する再検索を避ける。
- 将来サービスを追加しても、既存患者データの作り直しが発生しない。
- 診療終了等の患者は通常一覧から外し、年度別アーカイブとして参照できる。
- 本台帳を研究レジストリや電子カルテの代替にしない。

## MVP3.5時点で固定しない事項

- CSVの列名、文字コード、ファイル分割単位
- 外来予約・外来リハ予約の出力方法
- 部署別の正式な役割・承認フロー
- 長期利用途絶とアーカイブ移行の最終日数
- 将来サービスの外部事業所マスタ連携方法

これらは実データのサンプルと院内運用を確認してから取込・運用仕様を確定する。
