# はじめてのExcelゲート — MVP5thの組み込み方と使い方

**ブックで始め、HTMLで入力し、ブックで保存して終える。** MVP5thでは、この一往復で押すボタンと、導入時に担当する作業を整理しました。

[MVP4thの説明書](../MVP4th/はじめての組み込みと使い方.md)と比較できるように、同じ「1〜7」の章立てにしています。Windows／JUST Calc／Edge／共有フォルダを使い、利用者のPCに追加ソフトやサーバーを入れない方針は変わりません。

> **現在の状態（2026年9月21日）**
>
> HTML・VBAのコードと開発用のひな型は作成済みで、自動テストは32件合格しています。ただし、**マクロ組み込み済みの完成ブック `MVP5th.xlsm` は未作成です。Windows／JUST Calc／Edgeの実機検証も未実施です。**
>
> この説明書の導入・日常操作は、完成ブックを作り、実機検証を終えた配布物を使うときの手順です。現在の開発用フォルダだけで、最後まで利用できる状態にはなっていません。確認済みの範囲は[検証記録](docs/verification.md)を参照してください。

## 作成から導入までの役割

1. **HTML作成者**が、JavaScriptをすべてHTML内に組み込んだアプリを通常どおり作り、そのHTMLを導入担当者へ渡します。この時点でExcelゲート専用の接続を組み込む必要はありません。
2. **1人の導入担当者**が、受け取ったHTMLのコピーを編集し、Excelゲートへの適合・動作確認・配布準備・共有場所への配置・初回設定まで一貫して行います。
3. **利用者**が、共有ブックからアプリを開いて使います。

以降の「適合」「検証」「配置」は、すべて同じ導入担当者の作業です。担当者間の引き継ぎや分業は前提にしません。改善度は、**この1人がHTMLを受け取ってから利用開始までに行う作業全体**で評価します。

マクロ組み込み済みの共通ブックは、Excelゲート本体の提供物として用意する方針です。これはアプリごとに別の導入担当者へ組み立てを依頼する工程ではありません。現在は、この共通ブックの完成が未完了です。

## MVP4thから、何が容易になった？

| 場面 | MVP4thの手順 | MVP5thの手順・実装 | 現時点の確認状況 |
| --- | --- | --- | --- |
| 入力を終える | 「出力してExcelへ戻る」 | 「入力を終える」。出力後にブックで押すボタンを案内 | HTMLで確認済み |
| ブックで保存・終了する | 保存ボタン→取り込み確認→成功通知→終了ボタン→終了確認 | 「保存して終了」→成功通知のOKで対象ブックを閉じる | VBAに実装、実機未確認 |
| 今回のファイルを判断する | 自動検出後、名前・日時・保存者を見て確認に答える | 自動検出・検証し、正常時は取り込み確認を省く | VBAに実装、実機未確認 |
| 途中で保存する | 「受け渡し用に出力」→通常と同じ取り込みボタン | 補助メニューの「途中保存の準備」→「保存して続ける」 | HTMLで確認済み、ブック実機未確認 |
| 導入先でブックを用意する | 形式を変えて保存、7モジュール取り込み、イベント貼り付け、マクロ名を指定して初期化 | 完成品を配置し、画面の「初回設定」を押す | 完成ブック未作成のため、導入の簡略化は未検証 |
| 導入担当者がHTMLの適合作業を始める | フォルダ作成・コピー・共通スクリプト追加・設定作成を手作業 | 一つのコマンドでコピーと接続ひな型を作成 | 自動テストで確認済み |
| 配布に必要なファイルを指定する | 設定にファイルを一つずつ列挙し、共通部品の版を指定 | 専用アプリフォルダから一覧を生成し、共通部品を配置・版指定 | 自動テストで確認済み |
| HTMLの業務データを接続する | 読込・書出し・閲覧制御をアプリごとに実装 | 同じ。ひな型はあるが、アプリ固有の修正・確認は必要 | 二つの既存アプリでHTML側を確認済み |

**通常の終了保存で、ブックへ戻った後の操作は5回から2回へ減る実装です。** ここでは「ボタンを押す」「確認に答える」「成功通知のOKを押す」をそれぞれ1回と数えています。正常なファイルを自動検出できる場合の比較で、入力・保存者名・画面切替・Edgeのタブを閉じる操作は含めていません。実機での所要時間の短縮は、まだ測定していません。

MVP4thにもファイルの自動検出はありました。MVP5thの改善は、通常時に利用者が内容を照合して取り込みを承認する操作を省き、保存と終了をまとめた点です。

## 1. 何をする仕組みなの？

共有フォルダのブックを入口にして、Edgeの業務画面で入力します。入力を終えたら、開いたままのブックへ戻って保存します。

```text
共有ブックで「編集する」
    ↓
Edgeで入力 → 「入力を終える」
    ↓  自分でブックへ画面を切り替える
ブックで「保存して終了」
    ↓
保存完了の通知を確認 → ブックが閉じる
    ↓
残ったEdgeの作業タブを閉じる
```

**Edgeの「入力を終える」だけでは、ブックには保存されません。保存できたかどうかは、ブックの完了通知で確認します。** 自動の画面切替やタブ終了は行いません。

裏側では、Edgeが保存用のファイルをダウンロードし、ブックが今回の編集に対応するものを探して取り込みます。通常の操作では、ファイルの中身や保存形式を覚える必要はありません。

### この説明書に出てくる言葉

| 言葉 | 意味 |
| --- | --- |
| 共有ブック | 全員が同じ共有場所から開く、保存先となるブック |
| HTMLアプリ | Edgeで開く業務画面。進捗ボードなど |
| 保存用ファイル | Edgeからブックへ入力内容を渡すファイル。困ったときだけ探すことがあります |
| 完成ブック | マクロと画面のボタンを組み込み済みの `.xlsm` ファイル |

ブックは共有場所のものを使い、Edgeには一時コピーしたHTMLを `file://` で開きます。この仕組みはMVP4thから継続しています。

## 2. 用意済みのアプリを使う場合

### 2-1. どちらを使うか選ぶ

| アプリ | 用途 | 開発用ソースの場所 |
| --- | --- | --- |
| プロジェクト進捗ボード | プロジェクトの進み具合を一覧で管理 | `apps/progress-board` |
| 改善ワークフロー | 改善活動の文書を作成・管理 | `apps/workflow-studio` |

この二つは、既存の画面と業務データ構造を維持して接続済みです。用意済みアプリを使う人は「3」のHTML編集を行いません。

現在の `dev-dist` は開発検証用です。この章は、**適合と実機検収が済んだ配布フォルダ**が用意されている場合の手順です。作成者から受け取った通常のHTMLを導入する場合は、先に導入担当者が「3」の適合作業を行います。

### 2-2. 配布フォルダ一式を共有場所へ置く

完成後の配布物は、次の構成です。これは現在の完成品の所在を示すものではありません。

```text
progress-board/
├─ MVP5th.xlsm           ← マクロ組み込み済みの完成ブック
├─ 使い方.md             ← 利用者向け
├─ 導入手順.md           ← 導入担当者向け
├─ 管理者向け復旧.md
├─ gate.config.json
├─ runtime-files.txt
├─ release-manifest.json
├─ runtime/              ← 業務画面と共通プログラム
├─ shared/
└─ data/                 ← 保存・復旧に使う保管場所
```

導入担当者は、配布記録 `release-manifest.json` の `mode` が `release`、`targetPlatformValidation` が `passed` であることを確認します。`最初に読む_検証用です.txt` があるものや、`MVP5th.xlsm` がないものは利用者向け配布物ではありません。

フォルダを丸ごと、全員で使う共有場所へコピーし、「4」へ進みます。ブックやHTMLだけを取り出すと動作に必要なファイルが欠けます。

**MVP4thとの差：導入先でテンプレートとVBAを組み立てる手順を、完成ブックの提供に置き換えます。** VBAの組み立てはExcelゲート本体の開発担当者が行い、アプリごとのHTML適合は導入担当者が行います。

## 3. 受け取ったHTMLを組み込む場合【導入担当者向け】

ここは、JavaScriptをすべて内包したHTMLを受け取った、1人の導入担当者の手順です。**HTML内のJavaScriptを確認・編集し、Excelゲートへ適合させます。** 業務JavaScriptを別ファイルへ分割する必要はありません。現状は、ひな型作成と配布準備にコマンドも使います。

### 3-1. 何を変更する必要があるか

自動化されるのは、ファイルのコピー、共通プログラムの読み込み追加、接続ひな型・設定の作成、配布ファイル一覧の生成です。

導入担当者は、受け取ったHTMLの内部を確認して、次の接続・調整を行います。

| 接続・調整すること | 確認する内容 |
| --- | --- |
| 読み込み | ブックから受け取った業務データを、アプリの画面と内部データへ反映する |
| 書き出し | 現在の業務データを、従来と同じ構造で返す |
| 閲覧制御 | 追加・編集・削除・ファイル取込・外部からの更新を止め、検索や表示切替は残す |
| 既存のブラウザ保存 | 連携中は以前のブラウザ保存からの復元・自動保存を止める。遅れて復元が走る場合も確認する |
| 未確定の入力 | 開いたままの入力欄やダイアログを確定する。取得できない場合は理由を示して出力を止める |

任意のHTMLを無修正で接続する機能ではありません。`file://` で動作するアプリが対象で、サーバー必須の機能や外部サービスへの依存は個別に確認します。

### 3-2. 元のHTMLから作業場所を作る

導入担当者の作業PCにNode.jsとMVP5thの開発用一式を用意し、**MVP5thフォルダ**で次のコマンドを実行します。利用者のPCにNode.jsは不要です。以下の元ファイルの場所・名前は例なので、受け取ったものに置き換えてください。

```powershell
node scripts/init-app.mjs "C:\作業\元アプリ\index.html" my-app my-business-app "わたしの業務アプリ"
```

| 指定するもの | 例と意味 |
| --- | --- |
| JavaScriptを内包した元のHTML | `C:\作業\元アプリ\index.html` |
| 作業用フォルダ名 | `my-app`。`apps/my-app` が新しくできます |
| アプリを識別するID | `my-business-app`。英小文字・数字・ハイフンを使い、運用開始後は変えません |
| 画面に表示する名前 | `わたしの業務アプリ` |

このコマンドは、受け取ったHTMLを `apps/my-app/index.html` へコピーします。HTML内のJavaScriptもそのままコピーされるため、別のJSファイルを集める作業はありません。元ファイルは変更せず、すでにある `apps/my-app` への上書きは拒否します。入口のHTMLには `<head>` と `</body>` が必要です。

画像やCSSだけを外部ファイルで参照している場合は、それらも元の位置関係で `apps/my-app` へコピーします。

### 3-3. 共通プログラムの読み込みは自動で追加される

作成されたフォルダには、コピーしたアプリのほかに次のファイルがあります。

| ファイル | 役割 |
| --- | --- |
| `index.html` | 共通プログラムと接続ひな型の読み込みを追加した入口 |
| `gate-adapter.js` | ツールが追加するExcelゲート接続用のひな型 |
| `gate.config.json` | 表示名・アプリID・業務データ版・入口の設定 |

MVP4thのように、共通スクリプト三つの読み込みを手で貼る必要はありません。ただし、この段階ではデータ接続は未完成です。

元アプリのJavaScriptはHTML内に残ります。`gate-adapter.js` と共通プログラムはExcelゲート側が追加するもので、作成者が別途用意するJSファイルではありません。現在のツールはこの接続ひな型を別ファイルで生成します。

### 3-4. そのアプリの「読込・書出し・閲覧」を接続する

まず、コピーした `index.html` 内のJavaScriptで、データの保持場所・読込・保存・画面更新の処理を確認します。同じ導入担当者が、HTML内の既存処理を調整し、`gate-adapter.js` のTODOをアプリに合わせた接続へ置き換えます。接続APIは引き続き `ExcelGate.connect` で、主に `load`・`exportData`・`setReadOnly` を実装します。

非同期に初期化するアプリは、`ready` に完了を待つ処理を渡せます。各接続処理もPromiseを返せます。HTML内の関数の内側だけでデータを保持している場合は、接続処理もその中へ移します。その場合、不要になった `gate-adapter.js` とその読み込みを削除します。具体例は[導入担当者向けのHTML適合手順](docs/adapter-guide.md)にあります。

既存の保存・出力ボタンも、連携中は隠すか共通の出力へ接続します。共通側の保存者名と操作欄を使うことで、保存方法の重複を避けます。

ひな型の `EXCEL_GATE_ADAPTER_TODO` は、接続を実装してから取り除きます。未完成のまま残っている場合、配布フォルダの作成は止まります。文字だけ消しても、アプリは接続されません。

### 3-5. 設定を確認する

ひな型作成時に、次の設定が自動で作られます。

```json
{
  "displayName": "わたしの業務アプリ",
  "appId": "my-business-app",
  "dataVersion": 1,
  "entry": "index.html"
}
```

業務データにすでに版がある場合は、`dataVersion` をそれに合わせます。アプリIDとデータ版は、表示上の飾りではなく、別アプリや異なるデータ形式の混入を防ぐための設定です。

MVP4thで手書きしていたファイル一覧と共通部品の版は、ビルドが生成します。標準では「閲覧あり」「保存者名必須」です。`apps/my-app` には配布対象だけを置き、業務データ・バックアップ・開発用資料を混ぜないでください。

### 3-6. 検証用・配布用のフォルダを作る【導入担当者の作業】

まずHTML検証用を作ります。

```powershell
node scripts/package.mjs --mode=development ./dev-output my-app
```

出力先は `dev-output/my-app` です。共通プログラムの配置と、必要ファイル一覧の生成まで一括で行います。これは完成ブックがなくても作れる開発用出力です。

続いて、Excelゲート本体の開発担当者が用意する[完成ブック](docs/build-workbook.md)を使い、導入担当者が実機検証用を作ります。完成ブックがまだ用意されていなければ、ここから先には進めません。

```powershell
node scripts/package.mjs --mode=candidate ./candidate-output my-app
```

Windows／JUST Calc／Edgeで[実機試験](docs/acceptance-test.md)を行い、その配布内容と一致する検収記録をそろえた後、通常配布を作ります。

```powershell
node scripts/package.mjs ./release-output my-app
```

完成ブックや検収記録がなければ、通常配布は作成できません。出力先は毎回新しい場所を指定します。稼働中のブックや `data` を上書きするためのコマンドではありません。

### 作成者から導入担当者へ渡すときの文章

> JavaScriptをすべて内包したHTMLアプリを渡します。業務画面と業務データ構造を維持し、HTMLのコピーを編集してExcelゲートMVP5thへ適合させてください。適合から動作確認・共有フォルダへの配置まで、導入担当者1人が一貫して行う前提です。

## 4. 保存用ブックの準備【最初の一回・導入担当者向け】

**HTMLの適合と実機検収が済んだ配布物を使います。** この章の配置・初回設定では、VBA編集やコマンド入力は不要です。「3」のHTML適合作業は、その前に導入担当者が行います。

### 4-1. 共有場所を決めて、フォルダ一式を置く

全員が使える共有場所へ配布フォルダを置きます。各PCで同じUNC表記、たとえば `\\server\業務\進捗ボード` を使います。初回設定で場所を登録するため、先に最終の置き場所を決めてください。

### 4-2. 完成ブックを開く

フォルダ内の `MVP5th.xlsm` をJUST Calcで開き、職場で認められたマクロ実行設定を使います。`MVP5th-template.xlsx` は開発用です。拡張子を変えるだけでは完成ブックになりません。

### 4-3. 画面の「初回設定」を押す

「初回設定」を押し、表示された共有ブックの場所を確認して設定を実行します。完了後、「編集する」「閲覧する」「保存して終了」「保存して続ける」などが表示されます。

適合と検証を終えた後の配置手順は、**フォルダを置く→ブックを開く→初回設定**です。ここまで同じ導入担当者が行います。設定後のブックは、移動・名前変更・各PCへのコピーをして使わず、全員が同じ共有場所から開きます。

### 4-4. 本当のデータを入れる前に、一往復試す

1. 「編集する」を押し、Edgeでテスト入力します。
2. 「入力を終える」→ブックで「保存して終了」と進め、完了通知を確認します。
3. 同じ共有ブックを開き直し、「閲覧する」で入力が残っていることを確認します。
4. 途中保存も試し、ブックと同じEdgeの編集画面を維持できることを確認します。
5. 二台のPCで、一人だけが編集でき、もう一人は保存済みの内容を閲覧できること、終了後に編集を交代できることを確認します。

各PCのEdgeのダウンロード先が、Windowsの「ダウンロード」と一致するかも確認します。通常保存で毎回ファイル選択が出る場合は、導入担当者が職場の設定方針に沿って調整します。Windows・JUST Calc・Edgeの製品名と版を記録し、同じ共有ブックの場所と「使い方.md」を全員へ案内してください。

MVP4thの既存データは自動移行しません。切り替え時は、同じ導入担当者がバックアップとデータの対応を確認して移行を検証します。詳細は[導入担当者向け説明書](docs/install.md)を参照してください。

## 5. 普段の使い方【利用者向け】

ここからは、準備と動作確認が済んだブックを使う人向けです。

### 5-1. 入力して、保存して、終わる

| 順番 | 操作する画面 | すること | 確認すること |
| --- | --- | --- | --- |
| 1 | 共有フォルダ | 案内された `MVP5th.xlsm` を開く | 全員で使う共有場所のブックか |
| 2 | ブック | **「編集する」** を押す | Edgeが開く。ブックは開いたままにする |
| 3 | Edge | 入力し、開いている編集ダイアログなどを確定する | 今回保存する内容になっているか |
| 4 | Edge | 上部の **「保存者名」** に名前を入力する | 同じ編集作業で入力済みなら、そのまま使える |
| 5 | Edge | **「入力を終える」** を押す | 次にブックで押すボタンが案内される。まだ保存は完了していない |
| 6 | ブック | 自分で開いたままのブックへ画面を切り替える | WindowsのタスクバーでJUST Calcを選ぶなど、通常の切替でよい |
| 7 | ブック | **「保存して終了」** を押す | 正常ならファイル選択や取り込み確認は出ない |
| 8 | ブック・Edge | 「ブックに保存しました」の通知でOKを押す。ブックが閉じたらEdgeの作業タブを閉じる | 追加の終了確認は出ない。他のブックは閉じない |

終了用の出力後は、Edgeでの編集を止めてブックで保存します。**完了通知が出なかったときは、保存できたと判断せず「6. 困ったとき」を確認してください。**

表の行数は説明のまとめ方で変わります。操作回数の比較は、冒頭の「ブックへ戻った後の5回→2回」を基準にしてください。

### 5-2. 保存用ファイルが見つからないとき

通常は自分でファイルを選びません。「今回の保存用ファイルがまだ見つかりません」と出たときだけ、次を確認します。

1. Edgeで「入力を終える」（途中保存なら「途中保存の準備」）を押したか、ダウンロードが完了したかを確認します。
2. まだ完了していなければ、ファイル選択には「いいえ」で戻り、完了後にブックの同じ保存ボタンを押します。
3. 別の場所へ保存した場合は、案内の「ファイルを選びますか？」に「はい」と答え、今回のファイルを選びます。保存先はEdgeのダウンロード一覧で確認できます。

ファイル名は `Excelゲート受け渡し_` で始まり、末尾は `.json` です。古い作業や別のアプリのファイルを名前だけ変えて使うことはできません。

出力を紛失した場合は、Edgeで **「同じファイルを再出力」** を押すと、直前と同じ内容を再びダウンロードできます。終了用の出力後は表示中の案内画面に、途中保存の出力後は **「途中保存・再出力」** の中に、このボタンがあります。

### 5-3. 途中で一度保存し、続けて作業したい

1. Edgeで入力を確定し、保存者名を入力します。今回の編集作業で入力済みなら、再入力は不要です。
2. **「途中保存・再出力」** を開き、**「途中保存の準備」** を押します。
3. ブックへ戻り、**「保存して続ける」** を押します。
4. 「途中の内容をブックに保存しました」の通知を確認します。
5. ブックは開いたまま、**同じEdgeの作業タブ**へ戻り、入力を続けます。

| 目的 | Edgeで押すもの | ブックで押すもの |
| --- | --- | --- |
| 作業を終える | 入力を終える | 保存して終了 |
| 途中で保存する | 途中保存の準備 | 保存して続ける |

終了用と途中用を取り違えたときは、ブックが案内を表示して止まります。途中保存の後でも、作業を終えるときはEdgeで「入力を終える」を押し、ブックで「保存して終了」を押してください。

ブックの保存結果はEdgeへ自動通知されません。途中保存の完了もブックで確認します。今回出力したファイルは、保存を終えるまで削除せずに残してください。

### 5-4. 見るだけのとき・ほかの人が編集中のとき

1. 同じ共有ブックを開きます。読み取り専用で開かれた場合は、そのまま閲覧に使います。
2. **「閲覧する」** を押し、Edgeで保存済みの内容を確認します。
3. 終わったらEdgeの閲覧タブとブックを閉じます。

ほかの人が入力中の未保存データは見えません。検索や表示切替はできますが、内容の更新はできません。まだ一度も保存していないブックには、閲覧するデータがありません。

閲覧画面は自動更新されません。最新の保存内容を見たいときは、自分の閲覧タブとブックを閉じ、共有ブックから開き直します。編集を交代するときも、前の人が終了した後で共有ブックを開き直してください。

### 5-5. 入力を保存せずにやめたい

ブックの **「閉じる」** を押します。未保存の作業について確認が出るので、破棄してよいときだけ「保存せずに終了しますか？」に「はい」と答えます。途中保存した内容は残りますが、その後の未保存の変更は引き継がれません。

残ったEdgeの作業タブも閉じます。次回は共有ブックの「編集する」から、新しく始めてください。

## 6. 困ったとき

| 状況 | すること |
| --- | --- |
| `MVP5th.xlsm` がない | 開発用資料です。完成品の配置・初回設定には進めません。Excelゲート本体の開発担当者が完成ブックを用意します |
| 「初回設定」が出ない・ボタンが動かない | 導入担当者へ連絡します。配布物と職場のマクロ設定を確認してもらいます |
| 保存用ファイルが見つからない | 「5-2」の手順で、Edgeの出力と保存先を確認します |
| 「保存して続ける／保存して終了」を押すよう案内された | 終了用と途中用が違っています。案内されたボタンを使います |
| 不整合・別の編集作業・出力の分岐などが表示された | 古いファイルを選び直して押し通さず、ブック・出力ファイル・表示されたメッセージを残し、管理者へ連絡します |
| 通信断などで保存できなかった | ブックを閉じず、接続を確認して同じ保存ボタンで再試行します。復旧できなければ管理者へ連絡します |
| 「保存は完了しましたが、ブックを閉じられませんでした」と出た | 「保存して終了」をもう一度押します。保存を重複させず、終了を再試行する実装です |
| Edgeに保存完了が表示されない | 保存結果はブックで確認します。Edgeとブックの常時通信はありません |
| 毎回ファイルを選ばされる | 導入担当者に、EdgeとWindowsのダウンロード先を確認してもらいます |
| 前回のEdgeタブが残っている | 古い作業タブを閉じ、共有ブックから新しく始めます |

保存が途中で止まった場合、関連ファイルを削除したり、共有フォルダを新品で上書きしたりせず、[管理者向け復旧手順](docs/recovery.md)へ進んでください。障害時の処理はコードに実装していますが、通信断・再起動・終了失敗の実機試験は未完了です。

## 7. 利用者へ配る短い説明

次の案内は、完成ブックの実機検証と導入時の確認を済ませてから配ってください。

> 1. 共有ブックを開き、「編集する」を押します。
> 2. Edgeで入力します。ブックは開いたままにしてください。
> 3. 入力を確定し、保存者名を書いて「入力を終える」を押します。
> 4. ブックへ戻り、「保存して終了」を押します。
> 5. 「ブックに保存しました」の通知でOKを押します。ブックが閉じたら、Edgeの作業タブも閉じます。
>
> 途中保存は、Edgeの「途中保存・再出力」→「途中保存の準備」、ブックの「保存して続ける」を使います。ブックで保存完了を確認したら、同じEdgeの画面で作業を続けられます。
>
> 見るだけなら、共有ブックの「閲覧する」を押します。
>
> 保存できなかったときはブックを閉じず、表示された案内を確認してください。

## 改善度合いを判断するときの見方

| 評価すること | MVP5thで減らした負担 | まだ残る負担・確認 |
| --- | --- | --- |
| 日々の終了操作 | 保存・終了のボタンと確認をまとめ、正常時のファイル照合を自動化 | ブックへ戻る一往復、保存者名、入力の確定、Edgeのタブ終了は残る |
| HTML作成者の作業 | JavaScriptをすべて内包した通常のHTMLアプリを作り、そのHTMLを渡す | Excelゲート専用の接続は1人の導入担当者が行う |
| 導入担当者のHTML適合 | 定型的なコピー・読み込み追加・設定生成・配布を自動化 | 業務データ接続・古い保存処理の停止・未確定入力・閲覧制御は、導入担当者が個別に編集・確認する。コマンド操作も残る |
| 導入担当者の配置・初回設定 | VBA組み込みを本体の開発担当者へ移し、初期化を画面のボタンにする | 完成ブックの作成・実機検証が未完了。共有場所・PC設定・導入時の動作確認は必要 |

MVP4thの「4-2〜4-5」にあったVBA組み込みの説明を、本書では[Excelゲート本体の開発担当者の手順](docs/build-workbook.md)へ移しています。**導入担当者の仕事は、HTMLの編集・適合から配置・初回設定までです。「フォルダを置く→ブックを開く→初回設定」は、そのうち適合後の配置手順だけを表します。**

HTML内にJavaScriptがまとまっていても、業務データと保存処理の確認・修正は必要です。適合・検証・配置を別の人へ分担することで負担が減るとは数えません。自動化で実際に省ける作業と、この1人に残る作業を比較します。現在は、追加された接続ひな型の編集や、必要に応じてHTML内へ移す作業も残っています。

現段階で評価できるのは、操作設計・コード・ブラウザ側の動作です。完成品としての使いやすさは、二つのアプリと二台のPCで[実機試験](docs/acceptance-test.md)を終え、導入担当者が適合・配置できるか、利用者が迷わず保存できるかを確認して判断します。
