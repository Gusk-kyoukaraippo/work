# アルボ配車 プロジェクト構想メモ

## 背景

老健の利用者を送迎する際に、どの順番で迎えに行くか、どの車で迎えに行くかを決める作業に大きな手間がかかっている。

現在は、1日あたり約30人の利用者を2台から3台の車で迎えに行っている。ルート決めには以下のような調整が必要で、すべて人手で行っているため、毎回1時間以上かかっている。

- 車ごとに車椅子を何台まで乗せられるかが決まっている
- 車椅子利用者をどの車に割り当てるかを考える必要がある
- 大きい車は小さい路地に入れないため、住所や道幅に応じて車両を選ぶ必要がある
- 利用者の住所を見ながら、効率のよい迎車順を人が判断している

このルート決め作業を段階的に支援・自動化して、作業時間と判断負荷を減らすことを目的とする。

## 前提条件・制約

システムは完全オンプレミスで動作する必要がある。

- 外部APIは使えない
- Node.jsも使えない想定
- HTML単体で動く仕組みが必要
- 利用者CSVを読み込むと、HTML上で地図表示やマッピングができる形を目指す

MVP1の対象地域は群馬県伊勢崎市。

利用者CSVには、住所が「群馬県伊勢崎市〇〇町 番地」のような形式で入り、番地は半角数字で出力される想定。

## 地図マッピングの方針

外部地図APIを使えないため、伊勢崎市の地図画像をHTML上に表示し、その画像上に利用者の位置をプロットする方式を検討する。

想定している仕組み:

- 伊勢崎市の地図をJPGまたはPNG画像として用意する
- 住所ごとに、地図画像上のX座標・Y座標を対応付けるマスタを作る
- 利用者CSVの住所をマスタと照合する
- 一致した住所の座標に点を表示する

例:

```csv
住所,X座標,Y座標
群馬県伊勢崎市〇〇町123,120,240
群馬県伊勢崎市△△町45,300,180
```

## MVP

### MVP1: 利用者住所の地図プロット

その日に回らないといけない利用者リストをCSVで読み込み、住所をもとに地図上へ点を表示する。

目的:

- 利用者の分布を地図上で見えるようにする
- ルート検討の土台を作る

必要な要素:

- CSV読み込み
- 伊勢崎市の地図画像表示
- 住所と座標の対応マスタ
- 地図上への点表示
- マッピングできなかった住所の一覧表示

### MVP2: 利用者属性による色分け

利用者リストに属性を追加し、地図上の点を色分けする。

想定する属性:

- 車椅子利用者
- 大きい車で入れない住所・エリア

目的:

- 車椅子対応が必要な利用者を一目で確認する
- 大型車で行けない利用者を一目で確認する
- 車両割り当ての判断をしやすくする

### MVP3: 車両別ルート案の可視化

利用者の点を線でつなぎ、車両ごとのルート案として表示する。

地図の右側などに、車両ごとの条件判定を表示する。

表示したい内容の例:

- この車両で車椅子人数が上限内か
- 大きい車が入れない地点を含んでいないか
- 車両ごとの担当利用者一覧
- ルート順

目的:

- 人が組んだルート案を確認しやすくする
- 「この車では可能 / 不可能」を判断しやすくする

### MVP4: ルート自動出力

最終的には、利用者リストと車両条件からルートを自動出力できる状態を目指す。

ただし、外部APIやNode.jsを使えない制約があるため、MVP4の実現難度は高い。

検討事項:

- HTML単体で実装できる範囲の最適化ロジック
- 車椅子上限、車両サイズ制約を満たす割り当て
- 完全自動ではなく、候補案を出して人が修正する形にするか
- 住所座標マスタの精度とメンテナンス方法

## 初期実装で優先すること

まずはMVP1として、CSVを読み込んで地図上に点を表示するところまでを作る。

初期実装では、最短経路や自動ルート最適化には踏み込まず、以下を優先する。

- HTML単体で動作すること
- 利用者CSVを読み込めること
- 伊勢崎市の地図画像上に点を表示できること
- 住所がマスタにない場合に気づけること
- 後からMVP2以降の属性や車両条件を足しやすい構成にすること

## 未決事項

- 利用者CSVの正確な列名・形式
- 住所座標マスタの作成方法
- 使用する伊勢崎市地図画像の入手元・ライセンス
- 地図画像の縮尺と座標単位
- 施設、利用者宅、車庫などの基準地点をどう扱うか
- 車両ごとの定員、車椅子上限、大型車可否などの設定形式
- ルート順を手入力で並べ替えるUIを作るか
- 印刷やPDF出力が必要か
