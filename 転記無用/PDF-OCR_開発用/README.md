# ScanScribe（完全オフライン・単一HTML版）

文字レイヤーを持たないスキャンPDFの文字範囲をマウスで囲み、日本語・英語OCRへ
かけるローカルアプリです。PDF.js、Tesseract.js、WASM、言語モデル、画面コードを
すべてHTML内へ同梱しているため、Webサーバー、インストール、インターネット接続、
PDFの文字レイヤーは不要です。

## 配布版

| ファイル | 容量目安 | 向いている用途 | 認識条件 |
|---|---:|---|---|
| `ScanScribe.html` / `ScanScribe-light.html` | 11.8 MiB | 従来相当の軽量版 | 最大2候補、整数化モデル |
| `ScanScribe-enhanced.html` | 11.8 MiB | モデル容量を増やさず画像条件を改善 | 最大8候補、ROI直接描画、傾き補正 |
| `ScanScribe-precision.html` | 38.3 MiB | 普段の高精度用途 | 最大8候補、横書きfloat `tessdata_best` |
| `ScanScribe-maximum.html` | 38.3 MiB | 待ち時間より候補比較を優先 | 最大12候補、横書きfloatモデル、文字単位の合議 |

最初に試す版としては `ScanScribe-precision.html` を推奨します。最大精度版は、1範囲を
複数の画像処理とページ分割条件で最大12回認識するため、文書や端末によってはかなり
時間がかかります。高DPIが常に正解とは限らないため、細かい文字には600dpi、通常の
印刷文字には360〜450dpiも比較してください。

`ScanScribe.html` は互換性のため軽量版と同じ内容です。どの版も単独でコピー・保存でき、
実行時に同じフォルダの別ファイルを読みません。

高精度モデル版の横書きfloatモデルは、すでにgzip level 9で圧縮した公式
`tessdata_best`をBase64化して同梱しています。Tesseract.jsのworkerがgzipを直接展開するため、
別途`DecompressionStream`は使いません。38.3 MiBの大半はgzip済み2モデル（合計24.6 MiB）と、
単一UTF-8 HTMLへ安全に格納するためのBase64表現です。

## 精度向上の内容

- 選択範囲だけをPDFから直接高DPI描画し、ページ全面の画素上限による縮小を避けます。
- 選択枠の外側を2.5〜4 PDFポイント広げ、文字端の切れを防ぎます。
- 小さな傾きを検出した場合だけ自動補正します。
- 原画像、コントラスト補正、Adaptive Otsu、Sauvolaを比較します。コントラスト補正は追加の
  全画素バッファを作らないテスト済み処理、Otsu/Sauvolaは同梱Tesseract/Leptonicaの実装です。
- 選んだ文字配置に近い複数のPSMを比較し、信頼度だけでなく候補間の一致度も評価します。
- 高精度モデル版と最大精度版は、公式 `tessdata_best` の横書き用日本語・英語floatモデルを
  固定コミットから同梱します。
- 最大精度版は一致した文字を位置ごとに合議し、一つの候補の局所的な誤りを補います。長文は
  先頭・中央・末尾を抽出して候補選択し、合議計算で画面が長時間止まることを防ぎます。

これらは異なる原稿条件に強くするための仕組みであり、すべてのPDFで精度向上を保証する
ものではありません。手書き、ルビ、複雑な表・数式、強い影、極端な圧縮、欠損した文字は
OCRが苦手です。保存前に原稿と照合してください。

## 使い方

1. 使用する `ScanScribe-*.html` をダブルクリックして現行ブラウザで開きます。
2. PDFを選び、対象ページを表示します。
3. 読みたい文字をマウスでドラッグして一つの四角で囲みます。
4. 言語、DPI、文字配置、複数条件比較を選びます。
5. 「この範囲をOCRして追加」を押します。
6. 必要な範囲を順番に追加し、結果を確認・修正してTXTまたはJSONで保存します。

操作対象は一度に一つの四角です。新しく囲むと前の四角を置き換え、認識済み結果は操作順に
残ります。デスクトップのマウス操作向けで、タッチ・ペン操作は実装していません。

## 保存した作業の再開

JSONで保存した読み取り履歴は、ブラウザを閉じた後でも次の手順で復元できます。

1. 元のPDFを通常どおり読み込みます。
2. PDF名の下にある「作業JSONを読み込む」で、以前保存したJSONを選びます。
3. 結果、手編集後の全文、処理時間、次の読み取り連番が復元されます。
4. 次の範囲を囲み、同じ結果の末尾へ続けて追加します。

読み込み前にJSONの形式・容量・連番・ページ・座標を検証し、元PDFのバイト数とページ数が
一致しない履歴は拒否します。ファイル名だけが異なる場合は確認を表示します。JSON version 3に
保存される辞書情報は名前と件数だけで、置換ルール自体は含みません。過去の補正済み文字列は
復元されますが、続きにも同じ辞書を使う場合は辞書JSONをもう一度選んでください。

## 動作確認用サンプル

「動作確認用サンプルを使う」は、文字を画像化してPDFへ埋め込んだ1ページのスキャン相当
サンプルです。テキスト層はありません。

~~~text
完全オフライン文字認識
文書番号 12345
LOCAL OCR SAMPLE
Document No. 2026-0717
~~~

## 補正辞書JSON

辞書はブラウザに保存されず、ページを開くたびに手動で選択します。

~~~json
{
  "version": 1,
  "name": "業務用語辞書",
  "entries": [
    { "from": "誤認識", "to": "正しい表記" },
    { "from": "株 式 会 社", "to": "株式会社" }
  ]
}
~~~

`from` は正規表現ではなく文字どおりに一致します。同じ位置では長い語を優先し、置換結果へ
辞書を再適用しないため連鎖置換は起きません。上限は5 MB、5,000件、`from` 合計100,000文字
です。例は `dictionary.example.json` にあります。

## オフラインと安全策

- CSPの `connect-src 'none'` とJavaScriptガードで外部通信を禁止します。
- OCR worker内も通信、追加script読込、子worker生成を禁止します。
- PDF、画像、OCR結果、辞書、ファイル名、パスワードを送信しません。
- PDF内のリンク、フォーム、JavaScript、添付ファイルは実行せず、描画結果だけをOCRへ渡します。
- PDFは128 MB・20ページまでです。版ごとにcanvas、埋込画像、OCR画素数の上限があります。
- OCR workerを同じ言語で再利用し、失敗時には一度だけ作り直します。
- workerの遅延イベントは、そのworkerを所有する実行だけへ反映し、終了処理は一度だけ行います。
- 中止時は処理中の一範囲だけを破棄し、追加済み結果と現在の四角を保持します。
- TXTには認識できた文字だけを入れ、失敗診断と候補情報はJSON履歴へ残します。
- `localStorage`、`sessionStorage`、IndexedDB、File System Access APIは使いません。
- 更新が止まった業務ブラウザ向けに、PDF.jsが必要とするデータ複製処理と
  `Blob.arrayBuffer()`を互換実装へ自動で切り替えます。PDF読込の一般エラーには
  画面へ診断コードも表示します。

高精度モデル版と最大精度版は選択ROIを最大30〜40メガ画素まで許容し、傾き補正後の画像も
同じ画素・一辺上限に収めます。大きな範囲・600dpi・多重認識を組み合わせるとメモリ使用量が
数百MBになる場合があります。ブラウザが不安定なら、範囲を小さくするかDPIを下げてください。

## 開発・検証

Node.js 20以降を使用します。全4版の生成と、ユニットテスト、固定画像OCR、資産ハッシュ、
CSP、外部参照の検査は次で実行できます。

~~~sh
npm test
npm run check
~~~

個別のコマンドは次のとおりです。

~~~sh
npm run build:single       # 軽量版と ScanScribe.html
npm run build:variants     # 全4版
npm run check:variants     # 全4版の単一HTML/CSP検査
npm run smoke:ocr          # 軽量モデル固定画像
npm run smoke:precision    # 横書きfloatモデルとハッシュの検査
npm run smoke:browser      # Chromeでfile://実行・サンプルOCR・通信遮断を検査
~~~

`smoke:browser`はGoogle Chrome / Chrome for Testing / Chromiumを自動検出し、隔離した一時
プロファイルで実行します。見つからない環境では`SCANSCRIBE_CHROME_PATH`へ実行ファイルを指定します。
サンプルOCRだけでなく、JSON保存・再読込後の追記、Clipboard API拒否時のフォールバック、
HTTP(S)/WebSocket通信が0件であることも確認します。

現在の固定テスト画像では、軽量モデルのTesseract信頼度は英語95・日本語85、高精度float
モデルは英語95・日本語87です。これは固定されたきれいな画像に対するエンジンの信頼度で、
一般文書の正解率ではありません。実文書ではモデルだけでなくROI描画、二値化、傾き、PSMの
影響が大きいため、用途に近いPDFで比較してください。

オフライン資産を固定元から再取得するときだけ開発時のネットワーク接続が必要です。取得後は
SHA-256を照合してから保存します。

~~~sh
npm run vendor:offline
npm run vendor:precision
~~~
