# MVP3.5 静的回帰テスト

外部パッケージを使わず、Node.js の標準ライブラリだけで単一HTMLとサンプルJSONを検証します。

```sh
node MVP3.5/tests/run-static-tests.mjs
```

検証内容は次のとおりです。

- HTML内JavaScriptの構文
- 外部スクリプト・外部通信APIへ依存しないこと
- DOM IDの重複、JavaScript・label・タブからの参照切れ
- MVP3の病床ボード、入院登録、転床、次回日程調整に必要な主要DOM・関数
- MVP3.5の難病患者台帳に必要な主要DOM・関数、8疾患区分
- schema v5の必須配列
- サンプルJSON内のID一意性、CP一意性、患者・入院・病床・サービス参照、日時の整合性

テストはCSVの列構成や予約連携方式を固定しません。これらは実データの出力仕様が決まった段階で追加します。

## リリース前の手動確認

静的テストだけではブラウザ操作と表示を保証できないため、次を順に確認します。

1. `MVP3rd/bed-control-2026-06-01_to_2026-08-31.json`（schema v4）を読み込み、病床帯、配置待ち、転床履歴が消えず、台帳用配列が補完される。旧 `patients.regular` だけを根拠に定期入院へ自動確定しない。
2. 病床ボードで既存予定を1日移動して「元に戻す」、配置待ちへ戻して再配置、未来の転床登録と取消を行う。同一病床重複、異性同室、整備時間重複の警告が従来どおり出る。
3. 「次回日程・部屋調整」で患者、性別、期間、希望部屋を指定し、候補検索から配置待ち登録まで完了する。候補表示中に別予定を登録した場合は、確定直前の再検証が働く。
4. 台帳で1人に複数疾患を登録し、「その他」には元病名を入力する。候補／確認済み／終了を切り替え、一覧と詳細へ同じ状態が表示される。
5. 台帳の「患者を台帳へ追加」から入院歴のない外来のみ患者を正式CPで登録し、疾患と外来診察の利用関係を追加する。入院を作成しなくても一覧へ1患者1行で表示され、同一CPは拒否され、同名・別CPでは確認が出る。
6. 外来診察、外来リハ、入院の利用関係を任意に組み合わせ、疾患・利用形態・入院パターン・病棟適応の各フィルターとキーワード検索を確認する。「予約情報未連携」が「予約なし」と表示されない。
7. 入院履歴が0回、1回、複数回の患者を開き、回数、最終入院、入院間隔の中央値、次回予定が正しい。複数回でも定期入院へ自動確定せず、職員が未確認／不定期／定期を変更できる。
8. 患者詳細の時系列で外来、外来リハ、入退院、調整記録が日付順に並ぶ。HTML記号を含む元病名・メモを入力しても、タグとして実行されず文字として表示される。
9. 台帳から「次回日程・部屋調整」へ進み、患者と確認済みの性別が引き継がれる。性別未確認患者では過去の選択値が残らず空欄になる。空床候補は本日の外来実績・疾患確認済み・病棟適応あり・入院予定重複なしの患者だけを表示し、自動順位付けしない。
10. 同一CPの重複登録を拒否し、仮CPから正式CPへの統合では入院、疾患、利用関係、イベント、入院パターン、調整記録が全て正式患者へ付け替わる。統合元患者が通常検索へ重複表示されない。
11. 変更後に一時保存し、再読み込みして台帳とMVP3のデータが復元される。schema v5 JSONを再読込しても配列やサービスカタログが重複しない。
12. 画面幅を狭め、3タブ、フィルター、一覧、患者詳細を操作できる。キーボードの左右キーで3タブを順に移動でき、各タブの `aria-selected` と表示パネルが一致する。
13. 1,000人・直近24か月相当のデータで検索、フィルター、ページ移動、患者詳細表示を確認し、操作不能な停止や顕著な入力遅延がない。

## 回帰しやすい箇所

- `activateTab` が2タブ前提のままだと、台帳から左右キーで移動した際に病床ボードへ戻る。
- `normalizeData` が配列を補完しないと、v4 JSON読込直後に台帳描画で例外になる。逆に `regular` から定期入院を自動生成すると職員確認の原則に反する。
- 台帳の更新で `renderAll` が呼ばれないと、病床ボード、配置待ち、相談画面へ変更が即時反映されない。
- 入院実績集計でキャンセル入院や未来予定を最終実績へ含めると、最終入院日と利用間隔が誤る。
- `patientId` ではなく氏名で結合すると同名患者が混ざり、CPを画面上の行キーにすると仮CP統合時に関連レコードが孤立する。
- サービスイベントの予約情報がない状態を「予約なし」と扱うと、誤った声掛け候補を作る。
- 患者詳細の編集後に検索結果やページ番号を初期化しないと、件数が減った際に空ページが残る。
- JSON読込時に既定 `serviceCatalog` を毎回追加すると、保存と再読込のたびに同じサービスが増える。
