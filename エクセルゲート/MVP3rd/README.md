# MVP3rd：一時保存・正式保存管理

MVP3rdは、成功したMVP2ndを土台に、操作の分かりやすさを改善していく修正版です。マクロ付きExcelを入口にしてHTMLで業務データを編集し、JSONをExcelへ取り込んで正式保存します。

MVP2ndの構想と実機操作との差、およびMVP3rdでの対応は、[MVP2nd → MVP3rd 実機差分・変更履歴](docs/mvp2-to-mvp3-change-history.md)に記録します。

利用者に見えるシートは、保護された `操作パネル` 1枚だけです。業務データは表へ変換せず、JSONのpayloadをそのままExcel内へ分割保存するため、オブジェクト、配列、入れ子、文字列、数値、真偽値、null、未知項目を共通VBAで扱えます。

## 実装済みの内容

- 操作パネルの6操作
  - `DXプロジェクト8段階ガイドを開く`
  - `閲覧する`
  - `編集する`
  - `一時保存ファイルをExcelに正式保存する`
  - `ログチェック（管理者向け）`
  - `終了する`
- 通常操作は、`閲覧する`・`編集する`、正式保存、終了の順に上から配置。`ログチェック（管理者向け）` は離れた管理者用区画に配置
- 淡い青・黄・緑の落ち着いた状態表示と、最新版だけの正式保存カード
- 前回の正式保存からの経過時間は、小さな参考情報として表示
- HTML起動時の利用者名入力（毎回空欄、1～50文字、制御文字不可）
- `作業途中`と`作業終了`の一時保存を分け、次に行う操作をボタン名で明示
- `作業終了用に一時保存して終了` 後は編集画面を消し、Excelへ戻る案内だけの最小画面へ切り替え
- 作業終了用の一時保存後の最小画面に`この画面を閉じる`を表示し、自動で閉じられない場合はタブを閉じる案内へ切り替え
- ダウンロードフォルダからの自動検出とファイル選択への切り替え
- 同じデータの二重取り込み防止、保存の枝分かれ検出
- Excel内JSONの20,000文字分割、文字数・CRC32検証
- acceptedへの原本保存、rejected、pending、sessionの各保管場所
- `PREPARED` を使った二段階確定と、確定途中からの再開
- 1分タイマーとJUST Calc向けの自動無効化
- 閉じる前の保存確認。PCへ作成しただけの一時保存ファイルは次回起動時に自動回復しない
- 読み取り専用時の閲覧専用表示と、編集・保存ボタンのグレーアウト
- 閲覧HTMLでは記名を自動スキップし、万一名前画面が残った場合も `記名せず閲覧する` で進行可能
- 閲覧や画面更新だけではExcelを変更済みにせず、終了時の不要な保存確認を抑止
- 閲覧起動では重複していた操作パネル更新と保存済みJSONの再minifyを省き、整合性確認を維持したまま軽量化
- `終了する` では、MVP3rdが最後のブックならJUST Calc自体を終了。ほかのブックが開いている場合はMVP3rdだけを閉じる
- 出力JSONを日本語の `DX推進委員会アプリ一時保存_` で始め、作成日時・作業途中／作業終了・保存者・1週間後の削除目安をファイル名へ表示
- 操作パネル下部に、Excelへの正式保存完了後の一時保存JSON整理についての静的な案内を表示
- 旧Edge系で`?.`が構文エラーになる環境でも名前入力を開始できる互換処理と、ローカル保存領域が禁止された場合の画面内フォールバック
- 旧Edge系にない`replaceChildren`や複数要素の`append`を使わず、基本的なDOM操作で業務フォームを描画
- 正式保存の記録だけを表示する管理者向け読み取り専用HTML。過去版復元はなし
- `管理者向け 保存ログチェック` HTMLの `閲覧を終了` 操作。通常利用者は操作不要。ブラウザが自動で閉じられない場合は、Excelへ戻る案内だけの画面へ切り替え
- 最終保存時刻を文字列として保持し、既存のExcel日付シリアル値も通常の日時表示へ補正

## `.xlsm` の組み立て（Mac）

このフォルダには、見た目を確認できる `.xlsx` 原本と、インポート可能なVBAソースを分けて収録しています。VBAプロジェクトのバイナリはExcelまたはJUST Calc自身が作る必要があるため、初回だけ次の手順で `.xlsm` に組み立てます。

1. Mac版Excelで `workbook/MVP3rd-operation-panel-template.xlsx` を開く。
2. `MVP3rd` フォルダ直下へ、Excelマクロ有効ブック `MVP3rd.xlsm` として保存する。`html` フォルダと `.xlsm` の相対位置を変えない。
3. VBAエディターを開き、次の順で標準モジュールをインポートする。
   - `vba/Mvp2Config.bas`
   - `vba/Mvp2Json.bas`
   - `vba/Mvp2Storage.bas`
   - `vba/Mvp2Panel.bas`
   - `vba/Mvp2Main.bas`
4. `ThisWorkbook` のコード画面へ `vba/ThisWorkbook.txt` の内容を貼り付ける。
5. VBAの `InitializeMvp2` を1回実行する。
6. 保存して閉じ、再度開いてマクロを有効化する。
7. Macでの組み立てが終わったら、`.xlsm` 単体ではなく `MVP3rd` フォルダ一式をWindows PCまたは共有サーバーへコピーする。
8. Windows版Excelで開き、マクロを有効化して実機受け入れテストを行う。Windows側で `.bas` を再インポートする必要はない。

`vba` 直下の `.bas` は、Mac版ExcelのVBAエディターへ直接インポートするためCP932（Windows-31J）で保存しています。`vba/utf8` はコードレビューと修正用です。VBAへは `utf8` フォルダのファイルではなく、必ず `vba` 直下のファイルをインポートしてください。

Macは `.xlsm` の組み立てと初期化に使用します。HTML起動、ダウンロードフォルダ検出、JSON取り込みなどの本運用はWindowsで確認してください。

詳しい手順は [vba-install.md](docs/vba-install.md) を参照してください。

## 通常の利用フロー

1. 利用者が `.xlsm` を開く。
2. 必要に応じて `DXプロジェクト8段階ガイドを開く` を押し、8段階の進め方を確認する。
3. `編集する` を押す。
4. HTMLで利用者名を入力し、業務データを編集する。
5. 必要なら `作業途中の内容を一時保存して、編集を続ける` を使う。この操作では一時保存ファイルをPCへ作成し、同じHTMLで編集を続けられる。
6. 作業を終えるときは `作業終了用に一時保存して終了` を押す。一時保存ファイルのダウンロード開始後、HTMLはExcelへ戻る案内だけの最小画面へ切り替わる。
7. Excelへ戻り、`一時保存ファイルをExcelに正式保存する` を押す。
8. 緑の正式保存完了表示を確認する。

`ログチェック（管理者向け）` は、Excelへ正式保存された記録を管理者が確認するための機能です。通常の利用者は操作する必要がありません。管理者が開いた場合は、確認後に画面下の `閲覧を終了` を押します。ブラウザの制限で自動的に閉じられない場合は、Excelへ戻る案内だけが表示されるため、そのタブを閉じてExcelへ戻ります。

## MVP3rdで修正した時刻表示

MVP2ndでは、`2026-07-16 12:34:56` のような最終保存時刻を通常形式のセルへ書いたとき、Excelが日付として自動変換し、内部の5桁程度のシリアル値で保持する場合がありました。終了確認はその値をそのまま連結していたため、`46100.123456` のような表示になることがありました。

MVP3rdでは、メタ情報を文字列形式のセルへ保存します。また、すでに数値へ変換されている最終保存時刻と編集開始時刻も読み出し時に日時へ戻し、終了確認では `yyyy/mm/dd hh:mm` 形式へ整えます。

共有サーバー上のブックが読み取り専用で開かれた場合は、操作パネルに閲覧専用の案内が表示されます。`編集する` と `一時保存ファイルをExcelに正式保存する` はグレー表示になり、`閲覧する`、`ログチェック（管理者向け）`、`終了する` だけを利用できます。ログチェックは読み取り専用でも管理者が確認できますが、通常の利用者は操作不要です。

`閲覧する` では保存者名を入力しません。閲覧用であることをHTMLへ二重に渡して名前入力を自動スキップします。閲覧だけでExcelを終了した場合は、操作パネルの表示更新を保存対象の変更として扱わないため、Excel標準の「変更を保存しますか？」は表示しない設計です。

閲覧起動の軽量化では、開く直前の操作パネル再描画と、Excel内ですでに検証・圧縮保存されているJSONの再minifyを省きました。文字数・CRC32確認とpayload構造の読み取りは維持します。ブラウザ自体の初回起動時間はWindows環境や既定ブラウザに依存するため、実機で効果を確認します。

`終了する`を押したとき、MVP3rd以外のブックが開いていなければ`Application.Quit`でJUST Calc自体を終了します。ほかのブックが開いている場合は、作業中のブックを巻き込まないようMVP3rdだけを閉じます。利用中のJUST Calcが古く、ブックを閉じてもプロセスや枠が残る場合は、JUST Calcの更新モジュール適用状況も確認してください。

出力JSONは、`DX推進委員会アプリ一時保存_20260716-1530_作業終了_佐藤花子_削除目安20260723_…json`のような日本語名です。作成日時は日本時間で前半に置き、ファイル選択画面で日時、作業途中・作業終了、保存者を判断しやすくしています。`削除目安`は作成日の1週間後です。ただし、日付だけを見て削除せず、Excelへの正式保存が完了した表示を確認してから整理します。変更前の`MVP3SAVE_`で始まるファイルとの互換性は持たせず、新しい日本語名だけを取り込み対象とします。

編集HTMLは、旧Edge系で構文エラーになるオプショナルチェーン`?.`を使用しません。`globalThis`がないブラウザでは従来のwindow相当を使用し、`file:`形式のローカルHTMLで`sessionStorage`が禁止されていても、開いている画面内の保存番号を使って編集とJSON出力を続行します。画面を再読み込みすると一時的な保存番号を維持できないため、編集HTMLは再読み込みせずに利用します。

業務フォームの再描画も、旧Edge系にない`replaceChildren`や複数要素の`append`を使用せず、`removeChild`と`appendChild`で行います。

Excelを閉じた後も残るのは、手順6の正式保存が成功した内容だけです。PCへ作成しただけの一時保存ファイルや、前回のExcelから開いたままのHTMLは、次回のExcelでは保存に使えません。

## JSONの扱い

HTMLが出力する共通外枠は `formatVersion: 2` です。VBAは外枠を検証しますが、payloadを表へ展開したり、項目順を並べ替えたりしません。Excel内では文字列外の空白だけを除去し、元のJSON原本はacceptedへバイト単位で保存します。

現在のHTMLは、異なるJSON構造を確認するための汎用JSON編集欄です。実際の業務画面へ置き換える場合も、共通外枠と保存処理を維持すればVBA側は変更不要です。詳細は [adapter-guide.md](docs/adapter-guide.md) を参照してください。

## 自動テスト

Node.js 18以降で次を実行します。

```bash
node --test tests/*.test.js
```

テストは、名前、JSON外枠、親子関係、ファイル名、sessionStorageの保存範囲、HTML文言、再ダウンロード、終了警告、VBA公開マクロ、タイマー、二段階確定、分割保存契約を確認します。

## 実機確認が必要な項目

VBAソースはExcel/Windows/JUST Calcの実機で最終確認してください。特に `Application.OnTime`、`Workbook_BeforeClose`、保護シート上の図形ボタン、Known Folder、`FileDialog`、共有サーバー切断中のファイル操作は製品差・環境差があります。

確認手順は [acceptance-test.md](docs/acceptance-test.md) にまとめています。

## 現時点の制約

- `.xlsm` へのVBAインポートは初回だけ手作業です。
- 汎用HTMLはJSONを直接編集する技術検証画面です。業務利用時は、対象データに合わせた入力画面へ差し替えます。
- ブラウザはダウンロードの完了を確実に通知できないため、HTMLは「ダウンロードを開始しました」と表示します。
- 過去版の閲覧一覧はありますが、利用者向け復元機能はありません。
- rejectedとacceptedからの復旧は管理担当の作業です。
