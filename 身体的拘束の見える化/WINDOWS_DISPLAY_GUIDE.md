# Mac制作 → Windows実環境 Web表示ガイド

最終更新: 2026-07-24

## 目的

Mac上のCodexやChromiumで作成したHTMLアプリを、WindowsのEdge・Chromeで表示したときに、日本語が細い、小さい、薄い、改行位置が変わるといった問題を減らすための共通ガイド。

単一HTML、`file://` 起動、院内ネットワークやオフライン環境を含むWebアプリで使用する。

## 今回確認できた問題

- Macではヒラギノが使われるが、Windowsではフォントの候補順により游ゴシックが使われ、細く見える場合がある。
- 同じ `font-weight` でも、実際に使われるフォントによって線の太さが異なる。
- `0.5rem` 前後の補足文字は、Macでは読めてもWindows実機では潰れやすい。
- 薄い文字色、小さい文字、細いウェイトが重なると、凡例・注記・表の分母などが特に読みにくくなる。
- 文字を太くすると字幅や改行が変わり、カード高やグラフの表示位置にも影響する。

## 新規アプリ用の基本CSS

最初に以下を入れ、アプリ固有のデザインを上から追加する。

```css
:root {
  --ink: #19302e;
  --muted: #53655f;
}

* {
  box-sizing: border-box;
}

html {
  font-size: 16px;
  -webkit-text-size-adjust: 100%;
  text-size-adjust: 100%;
}

body {
  color: var(--ink);
  font-family:
    "Hiragino Kaku Gothic ProN",
    "Hiragino Sans",
    "BIZ UDPGothic",
    "Meiryo UI",
    "Meiryo",
    "Noto Sans JP",
    sans-serif;
  font-weight: 500;
  text-rendering: optimizeLegibility;
}

button,
input,
select,
textarea {
  font: inherit;
  color: inherit;
}

small,
.caption,
.meta,
.note {
  font-weight: 600;
}

@media (min-width: 1600px) and (min-height: 900px) {
  html {
    font-size: 17px;
  }
}
```

フルHD用の `17px` 指定は、情報密度の高い画面で有効だった設定例。画面全体の高さや改行に影響するため、必ず実データで確認してから採用する。

## フォントのルール

- Macではヒラギノ、Windowsでは `BIZ UDPGothic`、`Meiryo UI`、`Meiryo` の順で使う。
- `Yu Gothic` をWindows向けの第一候補にしない。
- `system-ui` だけに依存しない。OSごとに日本語の見え方が大きく変わる。
- `font-weight: 500` が400相当で表示されるフォントもある。小さい補足文字は600以上を個別に指定する。
- ページ全体を700にしない。見出し・数値・本文・補足の強弱がなくなる。
- ボタン、入力欄、選択欄には本文のフォントを継承させる。
- 外部Webフォントは、院内ネットワークやオフライン環境で読み込めない可能性がある。ローカルHTMLではOS標準フォントを基本とする。
- `text-rendering` やフォントスムージング指定だけで改善したと判断しない。実際のフォント、サイズ、ウェイト、色を確認する。
- `-webkit-font-smoothing: antialiased` はMac側を細く見せることがあり、Windows対策としては使わない。

## 文字サイズと太さの目安

| 用途 | 推奨サイズ | 推奨ウェイト |
| --- | ---: | ---: |
| 通常本文・説明 | 14〜16px | 500以上 |
| 重要な操作説明 | 12〜14px | 600以上 |
| カードの補足・表の分母 | 10〜12px | 600以上 |
| グラフの軸・日付 | 11px以上 | 700〜800 |
| 見出し・主要数値 | 画面に応じて拡大 | 700〜900 |

- 重要な説明や操作を10px未満にしない。
- 10px前後を使う場合は、補助的な情報に限定し、600以上のウェイトと十分なコントラストを確保する。
- `rem` を使う場合も、最終的にWindows実機上で何pxになるかを確認する。
- SVGグラフには `font-family: inherit` を指定し、軸文字はCSSの固定pxで読みやすさを確保する。

```css
.chart-svg {
  font-family: inherit;
}

.chart-axis-text {
  fill: #647770;
  font-size: 11px;
  font-weight: 800;
}
```

## 色とコントラスト

- 通常文字は背景に対して4.5:1以上を目安にする。
- 補足文字を薄くするときも、文字色そのものを調整し、`opacity` だけで薄くしない。
- 白背景の補足文字では、`#53655f` 程度の濃さを一つの基準にする。
- 薄い緑・灰色のカード上では、白背景よりコントラストが下がるため個別に確認する。
- 色だけで状態を伝えず、ラベル・記号・数値も併用する。

## レイアウトを崩さない調整順

文字を太く・大きくすると、カードの高さや改行位置が変わる。次の順で調整する。

1. Windows向けフォントの候補順を修正する。
2. 薄い文字色を濃くする。
3. 補足文字・凡例・注記だけを600以上にする。
4. 小さすぎる文字だけを段階的に大きくする。
5. 収まりが悪くなった場合は、文字を再び小さくせず、カードの余白・要素間の隙間を先に詰める。
6. テキストを含む要素は固定高を避け、`min-height` と自然な折り返しを使う。
7. フォント変更後に、ボタン幅、表の列幅、凡例の改行、グラフの下端を再計測する。

## Windows実機での確認項目

Macのレスポンシブ表示だけで完了とせず、最終判断はWindows実機で行う。

### 環境

- EdgeまたはChrome
- ブラウザ倍率100%
- Windows表示倍率100%と125%
- `file://` で使うアプリは、実際にローカルファイルとして開く
- 実運用と同じCSV・JSONなどを読み込む

### 画面サイズ

- 1920 × 1080: フルHD実環境
- 1366 × 768: 一般的なノートPC
- 1265 × 720前後: ブラウザのタブ・アドレスバーを除いた狭めのPC表示
- 390 × 844: スマホ対応がある場合

### 重点確認箇所

- 補足説明、凡例、注記
- 表の分母、期間、単位
- グラフの軸、日付、基準線ラベル
- ボタン、フォーム、プレースホルダー
- 無効状態、警告、ステータス表示
- モーダルや全画面詳細
- 文字の欠け、重なり、不自然な改行
- ページ全体の横スクロール
- 重要グラフが想定した画面範囲に収まるか

可能ならEdgeの開発者ツールで `Rendered Fonts` を確認し、実際に `BIZ UDPGothic` またはメイリオ系が使われていることを確認する。

## 完了条件

- Windows実機で本文・補足・凡例が無理なく読める。
- 重要な情報が細い文字や薄い色だけで表現されていない。
- 1920 × 1080と狭いPC表示の両方で、文字の欠け・重なり・ページ全体の横スクロールがない。
- フォント変更前後で、集計値や操作結果が変わっていない。
- Windows実機のスクリーンショットをMac側の表示と比較して確認している。

## MVP6thで実施した修正記録

2026-07-24、Windows Edgeの1920 × 1080スクリーンショットで、補足文字・凡例・月次表の文字が細く見える問題を確認した。

実施内容:

- `Yu Gothic` 中心の候補順から、ヒラギノ → `BIZ UDPGothic` → メイリオ系へ変更
- 本文を500、補足文字を600へ変更
- 補足文字色を `#657471` から `#53655f` へ濃色化
- グラフ軸を11px・800、基準線ラベルを11pxへ変更
- 1600 × 900以上ではルート文字サイズを17pxへ拡大
- 文字を小さく戻さず、週次カード上部の余白を詰めて折れ線グラフの収まりを維持

確認結果:

- 1920 × 1080、1265 × 720、390 × 844でページ全体の横はみ出しなし
- 1265 × 720では、週次カード上端を画面上端に合わせたときに折れ線グラフ全体が画面内に収まる
- 実CSV読み込み後も、3.4%、3.2%、8人などの主要集計値は変更なし
- ブラウザのエラーなし
