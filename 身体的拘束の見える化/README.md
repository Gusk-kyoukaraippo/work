# 身体的拘束の見える化 — 共通ルール

このファイルは、`MVP1st`、`MVP2nd`、および今後作成するすべてのバージョンに共通する実装条件と表示ルールを定める。

## 実行環境

- 各バージョンは、単一の `index.html` として作成する。
- CSSとJavaScriptは、すべて `index.html` 内に記述する。
- 外部JavaScript、外部CSS、外部ライブラリは使用しない。
- Webサーバーは使用せず、`file://` から `index.html` を直接開いて起動する。
- 外部への通信やデータ送信は行わない。
- IndexedDB、LocalStorage、SessionStorageは使用しない。
- File System Access API（`showOpenFilePicker`、`showSaveFilePicker`、`showDirectoryPicker`など）は使用しない。
- CSVの選択には、通常の `<input type="file">`、`webkitdirectory` を指定したフォルダ選択、またはドラッグ＆ドロップを使用する。フォルダ選択時は、`身体拘束実施者統計_YYYYMMDD-YYYYMMDD.csv` と `身体拘束実施一覧.csv` をファイル名に依存せずヘッダーで自動判別する。
- 選択されたデータはブラウザの一時メモリだけで処理し、端末には保存しない。
- 画面を閉じたとき、読み込んだデータは残さない。

## Mac制作・Windows実環境の表示互換性

- 今後作成するHTMLアプリは、[Mac制作 → Windows実環境 Web表示ガイド](./WINDOWS_DISPLAY_GUIDE.md) のフォント候補順、文字ウェイト、コントラスト、実機確認手順を適用する。
- Mac上の表示確認だけでは完了とせず、Windows実機のEdgeまたはChromeでも確認する。
- 特に補足文字、凡例、表の分母、グラフ軸は、小ささ・細さ・薄さが重ならないようにする。

## 病棟・病室の分類と表示名

病室番号は、全角・半角の数字を同じものとして扱ってから判定する。

### 6階

- 地域包括ケア病棟に含める病室は、`601`、`602`、`603`、`605`、`606`、`607`、`608`、`610` のみとする。
- 上記以外の「6」から始まる6階の病室は、`6階病棟（回復期）` と表示する。
- 地域包括ケア病棟と回復期は、同じ6階でも別区分として集計・表示する。

### 3階

- SCU病棟に含める病室は、`311`、`312`、`313` のみとする。
- 上記以外の3階の病室は、`3階病棟（SCU除く急性期）` と表示する。
- SCU病棟とSCU以外の急性期は、同じ3階でも別区分として集計・表示する。

### 4階

- 階数として表示するときは、`4階` とする。
- 病棟区分として表示するときは、`障害者病棟（4階）` とする。

## 実装時の優先順位

1. 病室番号を全角から半角へ正規化する。
2. 6階と3階は、上記の病室番号ルールで区分を決定する。
3. 集計、表、グラフ、注記では、このファイルで定めた表示名を統一して使用する。
4. 新しい画面や集計を追加するときも、既存データの表記揺れではなく、この共通ルールを優先する。

## 退院日の病室補正（MVP4th以降）

文字の全角・半角を施設識別には使用しない。

1. `日付(在院情報)` と `退院日(入退院歴)` が同じ日は、有効な `退院時病棟`・`退院時部屋` を優先する。
2. 退院時病室が空欄または院内病室として無効な場合は、有効な当日の `病棟`・`部屋` を使用する。
3. 当日の病室も無効な場合に限り、同じ患者コード・入院歴の直前の有効な院内病室を使用する。
4. いずれも確認できない患者日は推測せず、`その他・未分類` として表示する。
5. 院内病室は、病棟名が院内病棟の定義に一致し、病棟階と病室番号が一致する組み合わせのみ有効とする。

## 患者日の重複除外（MVP4th以降）

- MVP4thでは、同じ患者コード・入院日・退院日・`日付(在院情報)` の複数行を1患者日にまとめる。
- MVP5thでは、退院日の空欄・確定値の更新で同一入院が分裂しないよう、正規化した患者コード・入院日・`日付(在院情報)` の複数行を1患者日にまとめる。
- まとめた行のいずれかに「身体拘束を実施」かつ「実施」があれば、その患者日は実施患者日とする。
- 読み込んだ元行数、統合後の患者日数、重複除外行数を画面に表示する。

## 患者詳細の暫定JSON（MVP5th）

- CSVにない氏名・年齢・性別と、解除に向けた検討内容は、患者コードと入院日の組み合わせで入院エピソードに紐づける。
- MVP5thでは、退院日が空欄から確定値へ更新されても同一入院を分割しないよう、患者コードと入院日が同じ行を同じ入院エピソードとして扱う。
- 手入力値はブラウザの一時メモリだけに保持し、通常のファイル選択とダウンロードでJSON入出力する。
- JSONには手入力値と照合キーだけを含め、CSVから再計算できる1週間の拘束歴は含めない。
- JSON読み込みは、同じ患者コード・入院日の入力を上書きし、それ以外の入力を残す統合方式とする。全置換したいときは、画面の「入力をクリア」後にJSONを読み込む。
- 形式は `mvp5-provisional-1` とし、後日の正式仕様確定時に更新する。
- 氏名や臨床コメントが入る可能性があるため、書き出したJSONは要配慮情報として取り扱う。

## 病棟別の日次割合グラフ（MVP6th）

- 最上段の最新7日カードは、SCUを含む病院全体の実施割合を最大の主指標とし、「加算対象外のSCUも含む」と明記する。隣にSCU除外後の割合、その次に重複除外した実施患者数を表示し、延べ実施患者日・延べ在院患者日は小さく表示する。
- 最新7日の推移は、積み上げ棒ではなく病棟区分ごとの折れ線で表示する。
- 各点は、その日・その病棟の「実施患者日 ÷ 在院患者日 × 100」で算出する。分母が0の日は0%にせず欠測として扱う。
- 縦軸は0〜15%で固定し、全体通則の15%基準を最上部に明示する。
- SCUも病棟別の折れ線として表示するが、全体通則15%の判定対象からは除外して注記する。15%を超える点は上端に実値を表示する。
- その他・未分類は病棟区分不明のため、この比較グラフから除外する。
- 折れ線と内容が重複する「病棟区分別の実施状況」カードは表示しない。
- 「この1週間の詳細を表示」では、最新7日のどこかで身体的拘束の実施記録がある患者を入院エピソード単位で重複なく一覧化し、各日の実施・非実施・非在院を表示する。
- 週間詳細は全画面で開き、「身体拘束実施一覧」CSVをRAWデータと同時に読み込んだ場合は、各日の「● 実施」の下に患者ごとの合計拘束時間を表示する。
- 身体拘束実施一覧は、患者コード・入院日・実施日でRAWデータの入院エピソードと突合する。時・分の両方が空欄なら「時間記録なし」とし、0時0分は有効な「0分」として扱う。
- 同じ患者・入院日・実施日に複数行ある場合、各行の時間を単純加算すると24時間を超える重複計上が起こり得るため、最長の合計実施時間をその日の表示値として採用する。
- 患者詳細の「現在の部屋」は、RAWデータの最新7日内にある最後の有効な病棟・病室記録を表示し、その記録日も併記する。
- 身体拘束実施一覧と一致した実施日には、`態様1`を「方法」、`拘束部位1`を「部位」として表示する。心身の状態は強調枠で表示し、同一日に複数の記録がある場合は値を失わないよう重複を除いて併記する。
- 患者詳細では病名、手入力の拘束種類、切迫性・非代替性・一時性の入力欄を表示しない。既存の暫定JSONとの互換性を保つため、旧JSONに含まれるこれらの値は読み書き時に保持するが、画面からは編集しない。
