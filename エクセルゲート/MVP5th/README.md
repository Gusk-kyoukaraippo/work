# Excelゲート MVP5th

**ブックで始め、HTMLで入力し、ブックで保存して終える**構成へ整理した次版です。MVP4thは変更していません。

| 用途 | Edge | 共有ブック |
| --- | --- | --- |
| 作業を終える | 入力を終える | 保存して終了 |
| 途中保存 | 途中保存の準備 | 保存して続ける |

通常保存では今回のファイルを自動検出し、ファイル選択・取り込み確認を省きます。終了保存は成功通知を一度表示して対象ブックだけ閉じます。保存失敗は閉じずに再試行し、終了だけ失敗した場合は二重保存しません。
閲覧、保存者名、既存業務JSON、排他・セッション照合・保存の復旧処理は維持します。定期タイマーやブラウザとの常時通信は使いません。

HTML作成者がJavaScriptをすべて内包したHTMLアプリを通常どおり作成し、1人の導入担当者がそのHTMLを編集してExcelゲートへ適合させます。同じ人が動作確認・配布準備・共有場所への配置・初回設定まで行います。改善度は、この1人がHTMLを受け取ってから利用開始までに行う作業全体で評価します。共通のマクロ組み込み済みブックはExcelゲート本体の提供物として用意する方針です。

## 開発

```sh
python3 scripts/adapt-references.py
python3 scripts/encode-vba.py
node --test tests/*.test.js
node scripts/package.mjs --mode=development ./dev-dist
```

HTML試験はPlaywrightとChromeまたはChromium版Edgeを使用します。`CHROME_PATH` で実行ファイルを指定できます。
ブックのレイアウト作成には `@oai/artifact-tool`、ネイティブ組み立てには開発PCのExcelを使います。利用者PCにはこれらの開発ツールは不要です。

完成ブックの組み立て後は `--mode=candidate` で実機検証用を作成します。`verification/target-acceptance.example.json` に沿って実測結果を記録し、通常配布はモード指定なしで作成します。
出力先の上書きは拒否します。利用中のブックとdataをビルドで置き換えないでください。
