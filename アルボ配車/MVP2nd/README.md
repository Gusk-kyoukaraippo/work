# アルボ配車 MVP 2nd 現状記録

作成日: 2026-07-03

## 位置づけ

この状態を時系列上の `MVP 2nd` とする。

当初の `../docs/initial_project_memo.md` では、MVP2は「利用者属性による色分け」として定義していた。ただし、実際の開発では、利用者属性の色分けより先に、配車設定で必要になる「車ごとに点を一筆書きでつなぎ、ルート順を確認する」機能を優先した。

そのため、現在の `index.html` は、元々のMVP2よりも `MVP3: 車両別ルート案の可視化` に近い状態になっている。一方で、車椅子、大型車可否、利用者属性による点の色分けはまだ未実装である。

## 現在できること

- HTML単体で起動できる。
- 外部API、Node.js、サーバーなしで動作する。
- 伊勢崎市の概略地図を表示できる。
- 実際の介護サービス利用者一覧CSVを読み込める。
- CSV先頭の帳票タイトル行を飛ばし、住所列を自動検出できる。
- `利用者氏名` 列を名前として読み取れる。
- Shift_JIS / CP932系のCSVを読み込める。
- 利用者名と住所を、地図上の点とラベルとして表示できる。
- 住所座標が未設定の利用者は、誤って地図左上に出さず、未対応住所として表示できる。
- 伊勢崎市以外の住所を、勝手に伊勢崎市住所へ補完しない。
- 地図をドラッグで移動できる。
- ホイールまたは `+` / `-` / `100%` ボタンで拡大縮小できる。
- 300%を超えても、点と利用者名ラベルが小さくなりすぎない。
- 近い点は表示上で少しずらし、完全な重なりを避ける。
- 車1、車2を初期状態として持つ。
- 車を追加できる。
- 選択中の車ごとに、点をクリックして一筆書きのようにルートをつなげられる。
- 車を切り替えても、別の車の最後の点から誤って線がつながらない。
- 右枠の接続リストに、選択中の車だけのルート順を表示できる。
- 接続リストには、順番、利用者名、住所を表示できる。
- 選択中の車について、最後に引いた線を1本戻せる。
- 選択中の車について、路線だけをクリアできる。
- 全車分のルートをCSV出力できる。
- ルート出力CSVには、出力日時、車両、順番、利用者名、住所、座標、次の利用者名、次の住所を記録できる。
- 使う人が誤操作しやすい、地図読み込み、利用者CSV、打点、点削除、マスター操作系のボタンは画面から外している。

## 構想と合っている部分

- HTML単体で動くという前提は守れている。
- 外部APIやサーバーを使わず、地図画像と内蔵住所データで動いている。
- 実CSVから利用者名と住所を読み取り、地図上に点を出す流れはできている。
- 未対応住所を見えるようにする方針は維持できている。
- 車両別にルート順を扱う方向性は、元々のMVP3の構想と合っている。
- 右側にルート順のリストを出す形は、元々の「車両ごとの担当利用者一覧」「ルート順」の考え方に近い。

## 構想からずれた部分

- 名前は `MVPセカンド` だが、元々のMVP2である「利用者属性による色分け」にはまだ進んでいない。
- 実際には、MVP2を飛ばしてMVP3寄りの「車両別ルート案の手動作成」を先に実装している。
- 車椅子、大型車不可、利用者ごとの都合、車両ごとの性質といった属性情報は、まだデータ構造として本格的には持っていない。
- ルート出力はできるが、元々のMVP4で想定していた「条件を満たすルートを自動で作る」ものではない。
- 誤操作防止のため、地図読み込み、CSV読み込み、マスター操作などの管理系ボタンは画面から外した。これは現場利用を考えた追加判断で、元々の構想メモには明記されていなかった。

## 現在の制約

- 住所座標は概略位置であり、正確な玄関位置ではない。
- 町域代表点と擬似オフセットを使っているため、番地単位の精度には限界がある。
- 軽量DB上で町域座標が欠けていた町は、周辺町域から概略補完して表示する。
- 補完座標は送迎順検討用の大まかな位置であり、正確な番地位置ではない。
- 車椅子利用者、大型車不可エリア、乗車人数などの条件判定はまだない。
- 車両ごとの性質、利用者ごとの性質はまだ本格的には保存していない。
- ルートは人が手動で作る。自動最適化はまだない。
- 作成したルートを画面内に保存・再読み込みする機能はまだない。
- 印刷用レイアウト、PDF出力はまだない。

## MVPセカンドとしての評価

元々のMVP2とは内容がずれているが、配車設定アプリとしては重要な「車ごとにルートを手動で組み、順番を確認し、後日用にCSV出力する」段階まで進んでいる。

評価としては、`元々のMVP2は未完了、元々のMVP3の一部は先行実装済み` と見るのが正確である。

## 次に進むなら

次は、元々の構想に戻して `利用者属性` と `車両属性` を扱えるようにするのが自然。

候補:

- 利用者に車椅子、歩行状態、大型車不可、希望車両などの属性を持たせる。
- 車両に車椅子上限、定員、大型/小型などの属性を持たせる。
- 点の色や形で、注意が必要な利用者を見分けられるようにする。
- 車ごとのルートに、条件違反があるかを右枠に表示する。
- 作ったルートを保存し、次回読み込めるようにする。
