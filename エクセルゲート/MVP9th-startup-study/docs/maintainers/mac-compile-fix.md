# MacへのVBA貼り付けで文字が変わったとき

通常の導入では実行しません。VBEでコードを組み込む本体保守作業の補足です。

MVP6系の組み立て時には、貼り付け元のバックスラッシュが保存済みVBA内で別の文字（U+0080）に変わった事例がありました。整数除算だけでなく、JSONやパスの文字列にも影響しました。

MVP8thの貼り付け素材は、この文字を直接含めず、文字列では `Chr$(92)`、整数除算では `CLng(Fix(...))` を使います。`scripts/prepare-mac-manual.py` はUTF-8とCP932の一致を確認し、貼り付け本文にバックスラッシュやU+0080があれば停止します。

## 貼り付けたコードを直す

1. AIが現在のUTF-8ソースとCP932を照合し、8個の標準モジュール用の最新 `.txt` と `ThisWorkbook.txt` を準備します。貼り付け中に素材を更新しません。
2. [Mac組み込み手順の一覧](build-workbook-mac.md#4-八つの標準モジュールを作りコードを貼る) でモジュール名を確認し、問題のある既存モジュールのコード欄全体を、対応する最新 `.txt` で置き換えます。一行だけ直したり、同名モジュールを追加したりしません。
3. VBEの「デバッグ」→「VBAProjectのコンパイル」を実行します。別のエラーが出た場合は、表示内容と強調行を確認します。
4. [初回設定ボタンを作る手順](build-workbook-mac.md#6-コードを確認し初回設定ボタンを作る) に従い、未初期化の原本を保存します。`InitializeGate` は実行しません。
5. `scripts/verify-workbook.py` で保存済みブックと現行ソースを再照合します。コードの見た目やボタンの表示だけで合格にしません。

現在の `GateJson` の該当行は次の形式です。

```vb
ReDim parts(0 To CLng(Fix(Len(jsonText) / PART_SIZE)) + 2)
```

MVP8thでは `GateSources` も追加されています。過去版の「五つだけを差し替える」手順は使わず、全8モジュールとブックイベントの照合結果に従います。
