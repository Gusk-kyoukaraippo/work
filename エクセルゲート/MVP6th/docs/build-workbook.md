# 共通の完成ブックを作る

本体リリースごとに一度、マクロ組み込み済みの共通原本を作ります。アプリを追加するたびに繰り返す作業ではありません。アプリの組み込みでは、AIがこの原本をそのまま配布物に組み合わせます。

**Mac版Excelで手作業する場合は、[Macで共通ブックを手作業で作る](build-workbook-mac.md) を使ってください。** 既存テンプレートと貼り付け用コードを用意してあるため、組み立て操作にWindowsやNode.jsは不要です。

## この手順の担当と、HTML組み込みとの関係

この文書は、**Excelゲート本体を作成・提供するAI・開発者向け**です。共通原本を自分で作る場合の操作は上記の手作業手順に分けています。アプリを追加するたびに、組み込み者・導入担当者へコマンド実行やVBAの組み込みを求めるものではありません。

HTMLの改修と共通ブックの作成は別の工程です。現在の `integrate.mjs` は、既に作成・照合された共通ブックを配布物へ入れます。共通ブックがない場合にExcelを起動してマクロを組み込む処理は含まれていません。HTMLの組み込みを先に進めても、原本が完成するまでは開発用の出力になります。

| 工程 | 作るもの・確認すること | 次に進める条件 |
| --- | --- | --- |
| 1. テンプレート準備 | 操作パネルの見た目を持つ `.xlsx` と、VBAの取り込み用ソース | 必要ファイルとソースがそろっている |
| 2. マクロの組み込み | Windowsのスクリプト、またはMacの手作業で、実際のExcelにVBAと初回設定ボタンを組み込む | ソース照合に合格した共通原本と `MVP6th.build.json` ができる |
| 3. アプリとの組み合わせ | 改修済みHTMLと共通原本を含む実機検証用フォルダ | 現在の本体・アプリに対するブラウザ試験が合格している |
| 4. 本体・アプリの実機確認 | 対象版のWindows／JUST Calc／Edgeでの操作結果 | 必要な本体・アプリの実機記録がそろい、「配布可能」になる |
| 5. 導入先での確認 | 配置したコピーの初回設定、保存・閲覧・二台での編集交代 | その共有場所での確認記録がそろい、「利用開始可能」になる |

原本は初期化せずに保管し、実機試験や導入にはコピーを使います。導入時に押す「初回設定」は共有場所などを登録する処理で、マクロを組み込む処理ではありません。

## Windows版Excelを使うビルド

本体開発側で、Windows版Microsoft ExcelとPowerShellを使えるPCを用意します。以下のテンプレート生成と文字コード変換には、開発環境のNode.js・`@oai/artifact-tool`・Pythonを使います。準備済みのテンプレートとソースをWindowsの開発PCへ渡し、マクロの組み込みだけをそのPCで実行することもできます。利用者PCにこれらの開発ツールやMicrosoft Excelを追加する手順ではありません。

以下の相対パスは `MVP6th` フォルダを基準にしています。AI・本体開発者が、各工程の出力を確認しながら進めます。

1. `scripts/build-workbook.mjs` で `workbook/MVP6th-template.xlsx` を作成します。Node.jsと `@oai/artifact-tool` を使用します。
2. `python3 scripts/encode-vba.py` でUTF-8編集元とCP932取り込み用ソースを同期します。
3. マクロプロジェクトへのアクセスが認められた開発PCで、PowerShellから `./scripts/assemble-workbook.ps1` を実行します。
4. スクリプトが新しいExcelインスタンスで7モジュールとブックイベントを組み込み、初回設定ボタンを作成します。保存・再読込後にソース一致、余計なVBAコードがないこと、未初期化の1シート原本であることを確認します。
5. `workbook/MVP6th.xlsm` と `workbook/MVP6th.build.json` が作成されます。後者は埋め込みソースの検証記録であり、JUST Calcの実行合格を表しません。

スクリプトはマクロのセキュリティ設定を変更しません。VBAプロジェクトへアクセスできない開発PCでは、組織の管理者にビルド方法を確認します。
開いている業務ブックには接続しません。作成する原本は未初期化で、共有場所や業務データを登録しません。
既存の生成原本は日時付きで保管してから更新します。

## Mac版Excel等で組み立てた原本

[画面操作から説明した手作業手順](build-workbook-mac.md) に沿って、共通7モジュールと既存のThisWorkbookへコードを貼り付けます。`GateShowSetupPanel` を実行して **MVP6th.xlsm** として保存します。`InitializeGate` は実行しません。
作成した原本だけを閉じた後、AIが `python3 scripts/verify-workbook.py` で埋め込みソース・初回設定ボタンを照合します。この検証にはAI側のPython環境にoletoolsが必要です。手作業する人や利用者PCへコマンド操作を求めるものではありません。
検証は実際のVBAプロジェクト、モジュールの過不足、文字列を含むソース一致、UTF-8とCP932の同期、未初期化の操作パネル、実マクロへのボタン接続を確認します。失敗時は成功記録を作りません。Pythonの最適化オプションでも検査は無効になりません。

AIからExcelへ操作接続できなくても、手作業で作成した実ファイルを受け取って照合できます。実ファイルが未作成・未照合の間は、原本作成を完了扱いにしません。拡張子の変更、別アプリのVBAの流用、プレビュー画像を完成ブックの代わりにする方法は使いません。原本の構造検証やMac上の実行は、Windows／JUST Calcの検収とは別です。

## 通常配布

共通原本を新しく作ると、検証対象の本体の照合値が変わります。原本がなかった時点のブラウザ合格記録はそのまま使わず、AIがアプリの `verify` を再実行し、`package` で実機検証用の一式を作成します。そのコピーを使って本体・アプリの実機確認を行います。

共通エンジンとアプリの実測結果は、AIが[検収手順](acceptance-test.md)に従って記録します。記録ツールが対象のハッシュを付けるため、人が転記する必要はありません。配布に必要な二種類の記録がそろってから通常配布を作ります。

導入先の共有場所・二台での確認は、配置後の別の記録です。その記録を追加するために配布物を作り直したり、初期化済みブックや `data` を上書きしたりしません。検収が参照するブックは未初期化の共通原本です。保存のたびに変わる稼働中ブックのハッシュとは照合しません。

VBAソースを変えた場合は共通原本の再作成・検証と該当する共通試験が必要です。HTMLアプリだけの変更では共通原本を再作成せず、アプリと導入先の必要な確認を行います。対象ソフトウェアの版が変わった場合、以前の環境での検収を自動的に適用しません。

開発用テンプレートには動くマクロはありません。`.xlsx` の拡張子を変更して完成品として扱わないでください。
